# run: colab-1789719173182820657 결과 ZIP을 실행 기록에 등록

무엇. `artifacts/inbox`의 `colab-results-1789719173182820657.zip`를 `tools/register_run.py`로 등록했습니다.
결과 ZIP의 파일 70개를 `reports/runs/colab-1789719173182820657/`에 텍스트로 풀었고 ZIP 바이너리는
커밋하지 않았습니다. 두 ZIP 해시·코드 커밋·실행 환경·시간·건수·원응답 여부는 같은 폴더의
`manifest.json`에 있습니다. 제출 ZIP 해시의 출처는 `artifacts/inbox/submit.zip`입니다.

왜. 이 등록은 `99ebbf1` 코드가 NVIDIA A100-SXM4-40GB, vLLM 0.26.0, CUDA 13.0에서 dev-debug 200건, dev 200건, sample 10건을 완주하고 Macro F1 0.3334641077017238을 남겼다는 것만 기록하고 대회 서버 제출 성공을 증명하지 않습니다.
수치는 실행이 남긴 파일에서 그대로 옮겼고 등록 과정에서 다시 계산하지 않았습니다.
등록 검사: 결과 ZIP SHA-256 `29afd226…9294f`, 제출 ZIP SHA-256 `b0e22de3…ae7fb`, 파일 70개 UTF-8 해독, 최대 파일 526KB로 50MB 한도 아래,
비밀정보 패턴 0건, ZIP 경로 이탈 0건. 이 문서는 초안이며 사람이 확인한 뒤 커밋합니다.

그 규칙은 한 응답 안의 24항목 전부가 함께 읽는다. 부재 5항목에 인용을 요구하자

프롬프트가 바뀌었으므로 이 차이를 churn으로 걸러낼 수 없다. 다만 −0.0385는 관측 churn
상한(0.003129)의 12배이고 여덟 항목이 같은 방향으로 TP를 잃었다. 한 회차의 뽑기로
보기 어렵다. 확정하려면 같은 코드로 한 번 더 돌린다.

## v14·v15·v17은 부재탐지와 다른 문제다 — 별도로 물어도 TP가 0이다

모델에게 맡길 필요가 없는 판단을 맡기고 있었다.

v14는 다르다. 양성 8건 중 4건이 관측 단계에서 막히고 인용도 절반만 낸다.
