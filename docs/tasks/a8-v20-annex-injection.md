## 1. 한 문장

**「중소 소프트웨어사업자의 사업 참여 지원에 관한 지침」 제2조와 `[별표 1]` 을 v20 판정

## 2. 왜 v20 이고 왜 별표인가 — 전부 실측이다

| 사실 | 값 | 출처 |
| --- | --- | --- |
| v20 현재 성능 | **F1 0.200** (TP 1 · FP 4 · FN 4) | `18f07e5` 회차 재생 |
| v20 의 판정 규칙이 있는 곳 | 지침 `[별표 1]` — **685자 표 하나** | 아래 원문 |
| 그 표가 프롬프트에 있나 | **없다** | `build_system_prompt` 는 항목명·비고만 넣는다 |
| 주입 크기 | 제2조 305자 + 별표1 629자 = **934자 ≈ 623토큰** | 조회 보고서 |
| 예산 초과 공고 | **0 / 200** | `baseline` 실측 `prompt_tokens` |

```
제2조(사업금액의 하한) ① 법 제48조제2항에 따른 사업금액의 하한은 별표 1과 같다.

[별표 1]
대기업인 소프트웨어사업자가 참여할 수 있는 사업금액의 하한(제2조 및 제3조 관련)
┃구 분                          │사업금액의 하한 ┃
┃매출액 8천억원 이상인 대기업   │80억원 이상     ┃
┃매출액 8천억원 미만인 대기업   │40억원 이상     ┃
```

**80억·40억이라는 숫자가 이 표 말고 어디에도 없다.** 제2조는 "별표 1과 같다" 라고만 하고,
`script.py` 에도 이 값이 없다. v20 은 **판정 규칙 전체가 한 표**인 유일한 항목이고,
그래서 주입의 인과를 가장 깨끗하게 잴 수 있다.

> 모델이 이 값을 가중치로 알고 있을 수도 있다. **그것이 이 실험이 실제로 묻는 것이다** —
> 조문을 주는 것과 모델이 이미 아는 것의 차이. 아는데도 안 쓰는 것이라면 조건 ②에서 걸린다.

**그리고 별표는 베이스라인 청커로 주소지정이 안 된다** — 부칙 뒤 꼬리에 있어
`^제N조(` 로는 못 닿는다. 1단계가 이 자리를 열었다.

## 3. 무엇을 쓰나 — 조회는 이미 있다

```python
from experiments import law_index
law_index.annex("중소 소프트웨어사업자의 사업 참여 지원에 관한 지침", 1)   # → Segment
law_index.article("중소 소프트웨어사업자의 사업 참여 지원에 관한 지침", "제2조")
```

항목표 인용 31개가 **31/31** 로 풀리고, 돌려준 조각이 제공 파일의 **원문 부분문자열**임을
검사 23개가 고정한다. **9라운드 독립 리뷰를 통과했고 P1 21건이 그 과정에서 나왔다.**

`resolve()` 는 **쓰지 않는다.** 이 작업은 법령과 주소를 알고 있으므로
`article()`·`annex()` 를 직접 부른다 — 그쪽에 모호함이 없다
(`law_index.py` 의 「알려진 한계」 참조).

## 4. 먼저 답해야 할 것 — **주입은 공고를 밀어낸다**

`script.py:1041` `fit_to_budget` 이 예산 초과 시 줄일 수 있는 것은 **공고 `max_chars` 뿐**이다.
법령을 넣으면 그만큼 공고가 잘리고, 잘리면 부재탐지의 완전관측 게이트가 닫힌다.

```
보관 회차 baseline 200건: 프롬프트 중앙 9,356 · p90 11,432 · 최대 12,137 토큰 (예산 14,272)
v20 조각 623토큰을 더하면 → 예산 초과 0 / 200        ← 그래서 v20 이다
(참고: v23 4,297토큰이면 94 / 200 초과)
```

**착수 전 통과 조건 ①** — 주입 후 200건 전부에서 `fit_to_budget` 의 `max_chars` 축소가
**0회**임을 CPU 로 확인한다. 한 건이라도 줄면 그 순간 이 실험은 v20 이득과 공고 절단
손해가 섞여 아무것도 못 가른다.

## 5. 어디에 넣나 — 세 후보

v20 은 `company_size` 호출의 `software_business`·`software_participation` 사실을 쓴다
(`verify_document_requirements`, `script.py:699`). 조문을 **어느 호출의 어느 자리**에
넣을지가 이번 설계 결정이다.

| 후보 | 어디 | 대가 |
| --- | --- | --- |
| **A. `COMPANY_SIZE_PROMPT` 에 참조 절로** | 기존 `[Provided Korean law]` 자리와 같은 모양 | 200건 전부 623토큰 증가. 다른 23항목 사실에 영향 가능 |
| B. v20 전용 추가 호출 | 새 단계 | 전건 추가 호출 한 단계 ≈ **+1,618초**, 여유는 **820초**. **시간이 안 된다** |
| C. `baseline` 24항목 호출에 | 그쪽이 v20 1차 판정 | company 가 덮어쓰므로 인과가 흐려진다 |

**A 를 기본으로 본다.** B 는 시간 예산이 막고, C 는 측정이 안 된다.
A 의 위험은 "다른 항목 사실이 같이 흔들리는 것"이고, 그것이 통과 조건 ②다.

## 6. 통과 조건 — 사전 등록

회차를 돌리기 **전에** 이 표를 고정한다. 돌린 뒤에 기준을 고치지 않는다.

| # | 조건 | 왜 |
| --- | --- | --- |
| ① | 주입 후 `fit_to_budget` 축소 **0 / 200** | 공고 절단과 섞이면 못 가른다 |
| ② | **v20 TP ≥ 3** 이고 control 보다 개선 | 현재 1. FP 를 0으로 해도 F1 0.333 이라 TP 회복이 필요하다 |
| ③ | v20 FP 가 control 이하 | 표를 주고 오히려 더 쏘면 실패다 |
| ④ | 다른 23항목의 반복 손실 없음 | A 후보의 고유 위험 |
| ⑤ | 출력 토큰 한도 실패 0 | astra 회차에서 필드를 더하자 4건 터졌다 |
| ⑥ | company 단계 **339.178초/200건** 이내 | `(1853/200)×0.96 = 8.8944`, 여유 820초 |

**Macro F1 은 판단 기준이 아니다.** 같은 설정 별도 회차의 churn 이 **±0.0157** 이다
(astra 회차1 0.580462 대 회차2 0.596129). v20 한 항목의 이득은 그 안에 묻힌다.
**읽을 수 있는 신호는 v20 의 TP/FP/FN 뿐이다.**

## 7. 순서

1. **CPU 사전 검증** — 조문을 얹은 프롬프트로 `fit_to_budget` 을 200건 돌려 조건 ① 확인.
   모델 호출 0. 여기서 막히면 회차를 안 돈다.
2. **배선 검사** — 보관 원응답에 새 소비 경로를 얹어 **v20 밖 0셀**을 확인한다.
   astra 의 `대역 배선 검사` 와 같은 모양이다.
3. **후보 구현** — `experiments/a8_v20_annex.py` 에 `activate()` 컨텍스트로.
   `script.py` 는 **안 고친다.** 프롬프트·스키마 변경이므로 재생으로는 못 재고 회차가 필요하다.
4. **검사** — 조건 ①②③의 계약을 `tests/test_a8_v20_annex.py` 로 고정.
   **가짜 초록을 만들지 마라** — 저장 CSV 를 세지 말고 후보를 실제로 적용해 비교한다
   (PR #81 라운드 1 지적).
5. **GPU 회차** — control/후보 각 dev 200건. `RUN_DIAGNOSTIC=True`.
6. **기록** — 회차 ID·24항목 지표·환경·시간·오답·실패 상태를 `reports/team-c/a8-v20-annex/` 에.
   무라벨 발화율도 같이(W5).
7. **독립 리뷰** — `sol` 셀에 `artifacts/review/` 파일로. PR #81 과 같은 절차.

## 8. 하지 말 것

- **검색을 붙이지 마라.** 항목표가 주소를 준다. 한국 법령 BM25 는 Recall@10 23.4%
  (arXiv:2604.06173), 이 저장소의 공고명↔고시 617행 BM25 는 분리도 0 이었다.
- **전체 법령을 넣지 마라.** 실측 0.2208 → 0.1847 이다.
- **v23·v9·v18 을 같이 넣지 마라.** v23·v9 는 94/200 예산 초과이고,
  한 회차에 여러 항목을 넣으면 인과를 못 가른다.
- **`resolve()` 를 런타임 문자열에 쓰지 마라.** 「알려진 한계」가 그 자리다.
- **Macro 상승을 성과로 적지 마라.** churn ±0.0157 안이다.
- **`script.py` 를 고치지 마라.** 후보 단계다. 고치면 보관 회차 재현 계약이 흔들린다
  (PR #81 `e722022` 에서 실제로 그 경계를 건드렸고 부작용을 기록했다).

## 9. 실패로 끝나도 남는 것

조건 ②를 못 넘으면 **후보를 기각하고 `archive/rejected/` 에 근거와 함께 남긴다.**
astra 의 v18 후보(`PR #80`)와 내 `a6_unbacked_competitive` 가 그 형식이다.

그리고 그때 남는 질문은 하나다 — **623토큰짜리 판정 규칙 표를 줬는데도 안 오른다면,
v20 의 벽은 조문이 아니라 무엇인가.** 지금 확인된 것은 v20 미탐 4건 중 3건이
**제안요청서가 실제로 없거나 완전관측 false** 라는 것이다
([A5 독립 분석](../../reports/team-c/a5-label-definition/five-stuck-analysis.md) §2).
그 셋은 조문으로 안 고쳐진다. **이 실험이 실제로 노리는 것은 나머지 하나와 FP 4건이다.**
