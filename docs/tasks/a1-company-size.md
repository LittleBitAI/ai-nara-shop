작업 ID / 제목: `a1-company-size` / v14·v15·v16·v17·v18 을 금액구간 × 기업등급 표 하나로 판정

## 이 티켓이 최우선인 이유

현재 서버 0.2978624361 (`57761ff`, 2026-09-18). dev 0.3719775476.
**24항목 중 8개가 정확히 F1=0 이고 그중 5개가 이 티켓의 항목이다** — v14·v15·v16·v17·v18.
dev 양성 33건이 통째로 버려지고 있다. Macro 상한 기여 **+0.20**.

`0` 이 평균에 그대로 들어가므로 나머지 16항목을 만점 내도 상한이 16/24 = 0.667 이다.
이 다섯을 못 살리면 0.5 에 못 간다.

## 실측 — 본문보다 이쪽이 맞다

### ① 금액 구간이 정답을 완벽하게 가른다

`meta.입찰추정가격`(없으면 `배정예산금액`) 기준. dev 200건 중 **금액이 없는 공고는 0건**이다.

| 구간 | 공고 수 | 그 구간에 있는 정답 양성 |
| --- | ---: | --- |
| 고시금액(2.3억) 이상 | 45 | **v14 양성 8건 전부** |
| 1억 이상 ~ 고시금액 미만 | 49 | **v15 양성 6건 전부** |
| 1억 미만 | 106 | **v17 양성 6건 전부** |

경계 근거는 이미 `script.py` 상단에 조문과 함께 있다 —
`NOTICE_AMOUNT_WON = 230_000_000`, `SME_BAND_FLOOR_WON = 100_000_000`.
**가로축은 이미 해결돼 있다. 만들 것은 세로축 하나다.**

### ② 그런데 금액 게이트만으로는 아무것도 안 는다 — 실측 +0.0001

모델이 **이미 구간 안에서만 발화**한다. v17 예측 40건 중 39건이 1억 미만이다.
구간 밖 발화를 0 으로 되돌리는 후처리는 죽은 후보다. 다시 제안하지 마라.

### ③ 모델 출력에 v14·v15 신호가 아예 없다

정답 v14 양성 8건에서 모델이 v13~v18 중 **하나도 발화하지 않았다.**

```

PPS-DEV-047  가격= 727,272,727   발화=없음        PPS-DEV-054  가격= 327,272,727   발화=없음
PPS-DEV-049  가격= 600,000,000   발화=없음        PPS-DEV-057  가격= 272,727,273   발화=없음
PPS-DEV-051  가격= 245,454,545   발화=없음        PPS-DEV-17   가격= 309,090,909   발화=없음
```

v15 양성 6건도 1건만 발화했다(그나마 v17 로, 구간 밖).
**없는 신호는 후처리로 못 살린다.** 프롬프트/호출 구조를 바꾸는 회차가 반드시 필요하다.

### ④ v17 오탐 37건은 전부 "소기업·소상공인" 인용이다

v17 은 **중소기업** 제한인데, 오탐이 인용한 문구가 거의 전부 **소기업·소상공인** 제한이다.

```
[PPS-DEV-02]  「중소기업기본법」 제2조에 따른 소기업자 또는 ... 소상공인
[PPS-DEV-26]  ...소기업( 소상공인 포함)으로서 <소기업·소상공인 확인서>를 소지한 자
[PPS-DEV-136] ...제2조의2(중소기업자와의 우선조달계약)에 의한 소기업 또는 소상공인
```

인용에 `중소기업` 이 있고 `소기업` 단독 언급이 없을 때만 1 로 두면
**v17 F1 0.130 → 0.333 (TP 3→2, FP 37→4)** 이다. 이미 쟀다. 이건 임시방편이고,
제대로 된 해법이 이 티켓의 결정표다.

### ⑤ v13 도 같은 축을 쓴다 — 확인됨

A2(경쟁제품 4항목) 작업에서 v13 의 판별축이 **"공고가 어느 기업 등급으로 제한했나"** 하나로
환원된다는 것을 확인했다. v13 양성 `PPS-DEV-077` 은 경쟁제품 입찰인데 소기업·소상공인
확인서를 요구해 위반이다. **세로축 추출기 하나가 v13·v14·v15·v16·v17·v18 여섯 항목을 먹인다.**
A2 는 이 축을 만들지 않고 기다린다 — 두 번 만들지 않는다.

## 만들 것 — 세로축 하나

공고의 **참가자격**이 허용한 기업 등급을 뽑는다. 문서 어딘가의 언급이 아니라 **참가자격 조항**이다.

| 값 | 뜻 |
| --- | --- |
| `중소기업` | 중소기업자까지 허용 (중기업 포함) |
| `소기업` | 소기업·소상공인으로 좁힘 |
| `없음` | 기업 규모 제한 없음 |

구분해야 하는 것: 법령 이름(`중소기업제품 구매촉진…`), 확인서 이름(`중소기업 확인서`),
제출 서류 목록의 언급은 **참가자격 제한이 아니다.** 지금 모델이 이 셋을 구분 못 해 v17 에
오탐 37건을 낸다. `소기업·소상공인 확인서`는 dev 200건 중 179건에 등장한다 — 낱말만으로는 못 가른다.

## 실행 경로 — N2 가 이미 절반 깔려 있다

`script.py` 에 N2 배선이 들어와 있고 **꺼져 있다**. 아직 한 번도 GPU 를 안 탔다.

```python
BAND_ITEMS: List[str] = []                  # ["v14","v15","v17"] 로 켠다
BAND_RANGES = {"v14": (NOTICE_AMOUNT_WON, None), ...}
BAND_QUESTION = {"v14": "일반물품 입찰의 참가자격을 중소기업으로 제한", ...}
```

설계의 요점이 주석에 이미 적혀 있다 — **v14 와 v17 이 같은 질문이 되고, 둘을 가르는 것은
금액뿐이며 그 판정은 코드가 한다.** 이 티켓은 그 질문을 v16·v18 까지 넓히고 세 값짜리
세로축으로 바꾸는 것이다.

## 측정 — 무엇으로 재고 무엇을 믿지 않나

1. **회차 간 Macro F1 차이는 신호가 아니다.** 같은 코드가 dev 0.2182 를 세 번, 0.2208 과
   0.2202 를 한 번씩 냈다. 4,800셀 중 29~45개가 회차마다 바뀐다.
   읽을 것은 **대상 항목의 TP/FP/FN** 이고 `tools/compare_runs.py` 가 낸다.
2. 노트북 `quality_pass` 를 채택 근거로 쓰지 않는다. churn 만으로 양방향으로 뒤집혔다.
3. 프롬프트·스키마를 바꾸므로 **보관 원응답 재생으로는 못 잰다.** Colab 회차가 필요하다.
   회차는 반드시 `RUN_DIAGNOSTIC = True` 로 돌려 원응답을 받는다 — 그래야 그 뒤의
   후처리 후보가 전부 GPU 0초가 된다. 지금 보관된 원응답은 `99ebbf1`(dev 0.333) 것이라
   제출본 프롬프트와 다르다.
   **2026-09-20부터 Colab 회차 횟수 제한이 없다.** 그러므로 채택 후보는 **같은 ZIP 으로
   한 번 더 돌려** 그날 그 코드의 churn 을 직접 잰다. 위 1의 기준(29~45셀,
   0.000008~0.003129)은 과거 열 쌍의 값이고 프롬프트가 바뀐 코드에 그대로 선다는 보장이 없다.
   회차가 싸졌다고 한 회차에 두 변수를 넣지는 않는다 — 아끼는 것이 아니라 답을 잃는 것이다.
   **늘어난 것은 회차뿐이다.** 제출은 여전히 하루 1회, 서버 시간은 여전히 7,200초다.
4. **무라벨 발화율 카나리를 반드시 돌린다.** dev 200건은 항목별 양성 5~8건으로 인위적으로
   채워진 집합이다. 규칙을 `open/train_unlabeled.jsonl` 6,000건에 돌려 dev 대비 발화율을 본다.
   과거에 이 검사가 v8 0.28배·v4 0.34배를 경고했고, 그 제출에서 dev 이득의 **50.8% 만**
   서버로 갔다. 배율이 낮다고 반려하는 기준은 아니지만 **반드시 보고한다.**
