## 측정 — 2026-09-20 갱신 반영

1. 대상 항목의 TP/FP/FN과 대상 밖 19항목 변화를 본다. 과거 열한 쌍의 churn
   29~45셀 / Macro F1 영향 0.000008~0.004689는 역사적 관측이며 새 코드의 허용선이 아니다.
2. 노트북 `quality_pass`를 채택 근거로 쓰지 않는다.
3. 프롬프트·스키마 변경은 Colab에서 잰다. Colab 회차 횟수 제한이 없어졌으므로 채택 후보는
   같은 ZIP으로 한 번 더 실행해 그날 그 코드의 churn을 직접 잰다.
   `RUN_DIAGNOSTIC=True`가 기본이며 두 회차의 원응답을 모두 보존한다.
   ZIP·실행 코드·모델/설정·입력이 같은지 확인하고 항목별 TP/FP/FN, 바뀐 셀과 공고,
   Macro F1 차이를 기록한다. 두 회차로 얻은 한 쌍도 보편적인 상한으로 만들지 않는다.
   한 회차에 한 가설을 유지한다. 늘어난 것은 회차뿐이며 제출 하루 1회, 서버 7,200초,
   여유 2,919초, 전건 추가 한 단계 약 1,618초, 정답 dev 200건은 그대로다.
4. 무라벨 6,000건의 항목별 발화율/dev 발화율을 반드시 보고한다.
   금액 구간 비율·mock 비율은 발화율 대용이 아니다.
   W5 갱신(`c0a1929`): 기업등급 결정표를 dev 원응답 재생으로 고치는 후처리 후보에도

   발화 건수·비율·배율을 나란히 보고한다. 무라벨 사실 추출 결과가 없으면 미측정으로 남기며
