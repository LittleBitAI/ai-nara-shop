## 판정 규칙 — 라벨링 전에 정한다

## 다시 세운 라벨러 — 사실만 읽고 판정은 코드가 한다 (2026-09-24, 실행 전에 적음)

사용자 판단: 라벨링이 모델 등급에 따라 갈린다면 모델이 아니라 공고를 구조적으로 읽게 하는 프롬프트가 문제다.
실제로 위 프롬프트는 법적 판정을 라벨러에게 맡겼고, 발췌에 든 20% 가감 단서(지방 4~6%)를 대회 정의가
쓰지 않는데도(dev 는 지방 2%·3%·4% 를 모두 1 로 둔다, 운영 `V21_FLOOR_LOCAL = 5.0`) 라벨러가 읽게 했다.
`049` 의 놓침이 그 모양이다.

새 설계. 라벨러는 조문 없이 공고에서 사실만 뽑는다(`question-v21-facts.md`).

| 키 | 값 |
| --- | --- |
| `joint_contract` | `allowed` · `barred` · `not_stated` |
| `method` | `공동이행` · `분담이행` · `주계약자관리` · `혼합` · `not_stated` |
| `min_share_percent` | 공고가 정한 구성원별 최소지분율(숫자) 또는 null |

판정은 코드가 운영과 같은 표로 한다 — `joint_contract != barred` 이고 `method != 분담이행` 이고
`min_share_percent < v21_minimum_share(rec)` 이면 1. 정보부족=true 는 1 로 센다(보수적).
판정 규칙 1~3 은 그대로 적용한다 — dev 20건 보정의 TP 셀 적중이 3/5 이하이면 반려, 무라벨 84건에서
