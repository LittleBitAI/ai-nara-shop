## 4. 핵심 구현 계약

1. 기존 company_size 필드 뒤에 `scope_review`, `scope_review_quote`를 추가한다.
   enum과 인용 길이 제한은 기존 scope 필드 계약을 재사용한다. 기존 필드를 새 뜻으로 바꾸지 않는다.
2. 기존 프롬프트를 유지하고 끝에 별도 재검토 지시를 영어로 붙인다. 법적 용어·원문은 한국어다.
   구매 목적물과 제공 고시 지정 범위/조건을 묻고, 제목 유사성·도구 언급·메타 코드 부재를
   근거로 단정하지 않는다. 혼합 구매·조건 미관측은 unknown 보존. ID·정답별 예외 금지.
3. 기존 사실의 verifier 결과를 먼저 계산한다. 사실 복사본의 scope·인용만 review 값으로
   바꿔 동일 verifier를 다시 계산하고 **v18 키만** 기존 결과에 덮어쓴다.
   검토 결과에 v18이 없으면 기존 값을 보존한다. 유효한 v18=0도 반영한다.
4. 새 필드 없는 과거 응답은 기존 경로 그대로 간다. 새 후보의 live 스키마에서는 필드를 요구한다.
   새 필드 누락을 성공 응답으로 처리하거나 unknown을 general/absence로 바꾸지 않는다.
5. wrapper는 기존 함수의 입력을 변경하지 않는다. 예외 시 임시 프롬프트/스키마를 복원한다.
   기존 정확 인용·카탈로그·금액·자격 역할·예외·완전관측 검사는 그대로 재사용한다.
6. 재검토 OFF는 새 두 필드를 무시하고 기존 verifier를 호출한다. ON은 위 wrapper다.
   **실제 후보 점수에 control의 기존 필드를 끼워 넣지 않는다.** GPU 호출은 공고당 기존 단계 1회다.

`scope`와 `scope_review` 불일치는 원문 근거를 감사할 대상이다. 새 값이 무조건 정답이라는
가정도, 두 값을 영구적으로 상충시켜도 된다는 가정도 하지 않는다.

## 6. Colab 실행 준비와 회차 기록

노트북 SHA를 고정하는 후속 문서 커밋이 생기면 실행 소스 동일성을 검사한다.
입력 파일은 clone으로 생긴다고 가정하지 말고 실제 필요 파일을 검사한다.
필요하지 않은 무라벨 전체 파일을 dev 전용 파일럿의 필수 조건으로 만들지 않는다.

회차마다 필수 기록: run ID·시작/종료·상태·소스/입력/프롬프트/스키마 해시·모델 리비전·seed·
문서/출력 예산·GPU/Python/vLLM/CUDA·단계/추론 시간·서버 환산·24항목 F1/precision/recall/
TP/FP/FN/support·오답 ID·변경 셀·인용/반환 이유·재시도/실패·부분 결과.
혼합 재생 F1과 전체 GPU/서버 점수를 구분하며 미측정 값은 null이다.

판정 기준은 [방법 문서](../../reports/team-c/a5-label-definition/five-stuck-how.md)의 CPU/GPU 조건을 따른다.
TP≥3이라는 절대 수만 넘고 control보다 개선이 없으면 성과가 아니다. 두 회차의 TP/FP/FN 방향과
원문 근거를 함께 보며, 기존 항목 손실이 반복되거나 시간 상한을 넘으면 채택하지 않는다.
통과해도 무라벨 발화율·전체 GPU·서버 검증은 후속 단계다.
