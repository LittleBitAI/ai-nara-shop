```powershell
  --output-dir reports/<담당>/head-$(git rev-parse --short HEAD)-replay

# 3) 후보를 끼운다. postprocess·verify_sme 중 정의한 것만 갈아 끼운다
python -X utf8 tools/replay_run.py --case reports/runs/colab-1789655036303880754/dev-debug `
  --candidate experiments/<담당>_candidate.py --output-dir reports/<담당>/<티켓>-replay

# 4) 채점하고 2)의 HEAD 재생 CSV와 대조한다. 보관 회차의 submission.csv를 --before로 쓰지 않는다
python -X utf8 tools/score.py --truth open/dev_labels.csv `
  --pred reports/<담당>/<티켓>-replay/submission.csv --output-dir reports/<담당>/<티켓>-score
python -X utf8 tools/compare_runs.py --items <대상> `
  --before reports/<담당>/head-<커밋>-replay/submission.csv `
  --after  reports/<담당>/<티켓>-replay/submission.csv
```

2)와 3)은 같은 HEAD에서 돌린다. 그 사이에 브랜치를 옮기거나 pull했으면 2)를 새 커밋으로 다시 만든다.

코드 확인: 기본 `build_system_prompt`는 항목명·비고·부재탐지 표시와 일반 지시를 전달한다.
대부분 항목의 구체적 적용 조건·예외·판단 절차는 명시하지 않는다. 이를 주요 실험 가설로 삼는다.
각 담당은 담당 항목의 적용 조건/필요 사실/예외/정상 반례를 제공 조문과 연결한 짧은 기준을 준비한다.
법령 전체를 주입하는 방식은 반복하지 않는다. 사람이 제공 근거를 확인한 영어 지시·한국어 법적 용어를
작은 항목 묶음부터 적용하고, 문서 관측→사실 추출→조건 비교 중 실패 지점을 구분한다.

실행 유효성은 모든 후보의 필수 조건이다. 최초 오류
`청크 내 62번 공고: 정상 모델 응답 재시도 실패 (ValueError)`의 실제 서버 원인은 미확정이다.
실패 복구를 유지하면서 안정성 확인과 성능 후보 개발을 병행한다. 서버 응답을 기다리며 전원이 멈추지 않는다.

이번 배정은 [설계](../design.md)의 역할을 묶은 구체적 파일 소유권이다.
실험 파일은 필요할 때만 만들며 전체 script.py 복사·새 프레임워크·대규모 pipeline 분리는 하지 않는다.
기존 함수·토크나이저·채점기를 재사용하는 작은 후보 함수로 시작한다.
후보 인터페이스는 공고 1건과 그 공고의 모델 출력만 받으며, dev 정답·다른 공고 통계는 받지 않는다.
공통 법령 파일은 읽기 전용이다. 서로 다른 clone·브랜치에서 작업하고 한 파일을 두 담당이 동시에 고치지 않는다.

각 티켓은 조사 → 실제 사례/반례 → 후보 구현 → CPU/토큰 검사 → 실제 비교 → 채택/반려로 진행한다.
한 티켓이 끝나면 다음 티켓으로 진행한다. A에게 다음 할 일을 매번 묻지 않는다.

## 12. 전달 양식·검사 명령

