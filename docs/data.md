# 데이터 계약

소유: 통합 담당. 제공 데이터 명세와 배포 README를 통합한 작업 계약입니다.
출처 이력은 [sources](sources.md). 원문 보관본을 읽지 않아도 이 계약을 적용할 수 있습니다.

## D1. 실제 파일

2026-09-16 로컬 파일을 직접 세어 확인했습니다.

| 경로 | 규모 | 사용 |
| --- | --- | --- |
| `open/train_unlabeled.jsonl` | 20,000건 | 자가 라벨 생성 입력; 전부 정상이라고 간주 금지 |
| `open/dev.jsonl` | 200건 | 로컬 검증 입력 |
| `open/dev_labels.csv` | 200행, 49열 | 정답. 항목별 양성 5~8건 |
| `open/data/test.jsonl.gz` | 10건 | 샘플 실행; 실제 평가 데이터 아님 |
| `open/sample_submission.csv` | 제출 형식 예시 10행 | 열 순서 참고 |
| `open/data/항목표.json` | 24항목 | 항목명·부재탐지·국가/지방 조문·비고의 단일 원본 |
| `open/data/정답스키마_디코딩.json` | JSON Schema | 모델 출력 형식; 정답 데이터 아님 |
| `open/data/법령패키지/법령/` | txt 23개 | 판정 근거 스냅샷 |
| `open/data/법령패키지/중기부고시/` | HWPX + CSV | 품목 대조는 제공 CSV 사용 |

배포 설명의 train/dev `.gz`는 이 checkout에서 이미 압축 해제된 `.jsonl`입니다.
실제 경로를 사용하며, 평가 입력은 여전히 `PPS_DATA_DIR/test.jsonl.gz`입니다.
샘플 ID는 `PPS-S-####` 형태이며 실제 평가 ID·건수에 이 패턴을 강제하지 않습니다.
dev에는 모든 항목의 위반 예시·근거 예시와 **정상 예시 112건**이 있습니다.
실제 평가 데이터 구성비는 dev와 다르며 공개되지 않았습니다.

항목표의 기준일·표기규칙·부재탐지·항목별 국가/지방 조문·비고는 [items](items.md)에 통합했습니다.
항목→조문은 고정 매핑이며 법령명·조문은 제출 출력 필드가 아닙니다. v24는 근거 법령이 해당 없음입니다.
법령 txt에는 이미지인 구간과 제외된 대형 별표가 표시됩니다. 텍스트에 없다는 이유로 원문에도 없다고 단정하지 않습니다.
고시 제2025-96호 HWPX의 세부 품목 조회는 함께 제공된 CSV를 사용합니다. 판정 스냅샷은 R11을 따릅니다.
JSON Schema는 vLLM structured outputs용 형식 제약이며 정답이 아닙니다.

## D2. 공고 1건

| 필드 | 타입·의미 | 보존할 조건 |
| --- | --- | --- |
| `id` | 비어 있지 않은 문자열 | 출력에 그대로 사용, 유일성 검사 |
| `docs` | `{doc_id, type, text}` 배열 | 공고문 1건 이상, 첨부 포함; 원문을 근거 대조용으로 보존 |
| `meta` | 등록 정보 객체 | 아래 21필드, `null`과 `"미입력"` 구분 |
| `dropped_doc_counts` | 길이 예산 초과로 제외된 문서 종류별 개수. 예: `{"제안요청서": 1}` | 비어 있으면 제외 없음; 아니면 미관측 문서가 있음 |
| `input_completeness` | bool 4종: 공고문_실재·추출_성공·무탈락·완전관측 | 불완전 입력에서 부재를 단정하지 않음 |
| `anon_applied` | bool | 배포본 true; 익명 토큰 복원 금지 |
| `assembly_policy_version` | 문자열 | 원본 조립 규약 버전 기록 |

train·dev·test 모두 JSONL 한 줄이 공고 1건입니다. 문서 종류는 공고문, 규격서, 과업지시서, 제안요청서, 예외공표서입니다.
텍스트는 NFC이며 표는 `|` 구분자로 행·열을 복원한 형태입니다. 줄·공백을 바꾼 텍스트를 원문 근거로 내지 않습니다.
위반이 첨부에만 나타날 수 있으므로 공고문만으로 판단을 끝내지 않습니다. 첨부 누락은 부재탐지 위반의 자동 근거가 아닙니다.

## D3. 등록 정보

| 묶음 | 필드 |
| --- | --- |
| 계약·입찰 | 적용계약법, 업무구분, 계약방법, 낙찰방법, 낙찰하한율, 입찰방법, 조달방식 |
| 금액·일정 | 배정예산금액, 입찰추정가격, 공고게시일자, 개찰예정일자, 긴급공고여부 |
| 자격·제한 | 소관구분, 공동도급구성방식, 정보화사업여부, 세부품명번호목록, 제한지역코드목록, 지역제한여부, 면허업종제한목록, 업종제한여부, 조항호내용 |

`null`은 값이 없음, `"미입력"`은 등록되지 않음이며 둘 다 “해당 없음”이 아닙니다.
빈 값 자체가 판단 재료일 수 있습니다. meta는 원칙적으로 본문과 정합하지만 v24는 불일치를 판단하므로 어느 한쪽으로 덮어쓰지 않습니다.
기관명·담당자·연락처·주소·공고번호는 익명 토큰으로 치환됩니다. 아래 남은 정보는 활용할 수 있습니다.

| 토큰 예시 | 해석 |
| --- | --- |
| `[수요기관(기초자치단체)\|지역=r1]` | 괄호 안 기관 유형을 판단에 사용 가능 |
| `[지역:r1\|단위=기초\|광역=경기도]` | 지역 계층을 판단에 사용 가능. 광역 시도명은 유지되며 같은 문서의 r1/r2는 서로 다른 지역 |

금액·날짜·수량·법령 조문·품명·규격은 익명화 치환 대상이 아닙니다.

## D4. 모델 출력과 제출 출력

베이스라인 모델 출력은 `v1`~`v24` 각각이 아래 객체인 JSON입니다.
파일 스키마에는 `판정` 래퍼가 있을 수 있으므로 기존 `decode_schema()` 처리와 일치시킵니다.

```json
{"v1": {"위반여부": 0, "근거문구": null}}
```

위 예는 항목 1개의 모양만 보여줍니다. 실제 응답은 24개 항목이 모두 필요합니다.
CSV는 `id,v1,...,v24,e1,...,e24` 순서의 **49열**입니다.
제출 경로는 `PPS_OUTPUT_DIR/submission.csv`(기본 `output/submission.csv`)입니다.

| ID | 출력 불변 조건 |
| --- | --- |
| D4-1 | 입력 ID 집합·건수와 출력이 일치하고 중복 없음. 팀 구현은 입력 순서도 유지 |
| D4-2 | `v` 값은 정수 0 또는 1. CSV 셀은 `0`/`1`; JSON 문자열·bool·확률·공란 불허 |
| D4-3 | 판단이 어려워도 v는 비우지 않고 0. 내부 상태에는 정보 부족과 확정 비위반을 구분 가능 |
| D4-4 | e는 원문 문서 안의 연속된 부분문자열, 500자 이하. 법령·meta에서 가져온 값만으로 대체 금지 |
| D4-5 | v=0이면 e는 빈 문자열. 부재탐지 v10·v11·v16·v18·v20은 v값에 관계없이 e가 빈 문자열 |
| D4-6 | UTF-8 without BOM, NFC, RFC4180 quoting 적용. 근거 첫 문자는 `=`, `+`, `@` 불가 |

근거를 정리·요약·교정하거나 떨어진 문장을 합치지 않습니다.
잘못된 e를 비워도 v의 정오가 자동으로 바뀌지는 않습니다. 근거 폐기율은 별도 품질 지표입니다.

## D5. 채점

항목마다 양성 클래스 기준 `F1 = 2TP / (2TP + FP + FN)`을 구하고 24개를 단순 평균합니다.
분모가 0인 로컬 부분집합은 팀 채점 규약으로 F1=0을 기록하고 양성 수를 함께 표시합니다.
dev 전체에는 24항목 모두 양성이 있습니다. 제출 점수의 최신 구현·평가 조건은 공식 평가 탭으로 확인합니다.

e열은 리더보드 점수에 포함되지 않지만 2차 평가에 사용됩니다.
dev 정답을 프롬프트 사례로 사용한 결과는 독립 검증 점수로 보고하지 않습니다.
자가 라벨은 공식 정답과 구분하며, 사람 검토 여부·생성 출처를 남깁니다.
전체 평가 데이터 채점·Private 정의·2차 반영 비중은 [contest E2](contest.md#e2-평가와-수상)를 따릅니다.

## D6. 실행과 오류 대응

베이스라인은 데이터 로드 → 고정 모델 제약 디코딩 → 근거 검증 → CSV 저장 순서입니다.
`--mock`은 모델 없이 입출력만 확인합니다. GPU 없이도 전처리·채점·출력 검증은 가능하지만 실제 고정 모델 실험에는 적절한 GPU 또는 임대 환경이 필요합니다.

| 상황 | 확인·처리 |
| --- | --- |
| 실행 직후 vLLM 실패 | 실행 진입을 `if __name__ == "__main__":` 아래에 둠 |
| 파일·모델 경로 오류 | `PPS_DATA_DIR`, `PPS_OUTPUT_DIR`, `PPS_MODEL_DIR`, `PPS_EMBED_DIR` 환경변수 사용. 개인 경로 하드코딩 금지 |
| 모델 다운로드 실패 | 추론 서버는 인터넷 차단. 모델 ID 다운로드 대신 서버 제공 경로에서 로드 |
| CSV 형식 오류 | D4로 ID 누락·중복·추가, 빈 값·확률·bool, 49열·근거·인코딩 확인 |
| LLM·임베딩 동시 로드 메모리 부족 | 동시 GPU 로드는 보장되지 않음. 임베딩 CPU 실행 또는 모델 로드 순서 설계 |
| 로컬·서버 결과 차이 | 이미지·모델 리비전·드라이버·vLLM 버전·시드 비교. 재현성은 같은 환경 범위에서 판단; 로컬 환경 자체는 자유 |
| 제출 후 점수 미표시 | 대기열과 실제 실패를 구분. 실행·대기 시간과 운영 제한은 [contest E3](contest.md#e3-제출-운영) |

고정 패키지 변경 금지는 R19, ZIP·시간·제출 게이트는 [rules](rules.md)가 소유합니다.
