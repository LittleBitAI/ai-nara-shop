# 대회 안내

기준: 사용자가 제공한 대회 안내·규칙·데이터 명세의 2026-09-16 정리본입니다.
2026-09-16 공식 규칙·평가·일정 탭을 재확인했습니다([확인 기록](tasks/t1-baseline.md#공식-운영-확인-2026-09-16)).
원문 보관본을 열지 않아도 아래 안내와 연결된 작업 문서로 작업할 수 있습니다.

## E1. 과제와 목적

나라장터 자체입찰 공고의 위반 소지를 선별하고 근거를 제시해 담당자의 검토를 지원합니다.
부당한 참가자격 제한 등 공정한 경쟁을 저해하는 공고를 대량으로 점검하려면 본문·첨부·등록 정보를 함께 읽어야 합니다.

| 구분 | 작업 계약 |
| --- | --- |
| 입력 | 입찰공고 1건의 공고문·첨부 텍스트와 나라장터 등록 정보. [data D2·D3](data.md) |
| 출력 | 24개 항목의 위반 여부 0/1과 근거 문구. [data D4](data.md) |
| 항목 | v1~v23은 관련 법령·예규·고시에 따른 위반, v24는 공고서와 등록값 불일치. [items](items.md) |
| 개발 대상 | 고정 LLM 기반 전처리·프롬프트·검색·후처리 파이프라인. 모델·자료 조건은 [rules R1~R14](rules.md) |
| 라벨 설계 | 별도 학습 정답은 없고 무라벨 20,000건과 dev 예시 200건을 제공. 자가 라벨 설계·생성도 과제에 포함. [rules A1~A3](rules.md) |

## E2. 평가와 수상

| 단계 | 제공 안내의 기준 | 팀이 준비할 것 |
| --- | --- | --- |
| 매 제출 | **전체 평가 데이터**로 채점. Private Score는 대회 종료 시점의 리더보드 점수 | 공개·비공개 부분집합으로 나눠 채점한다고 가정하지 않음 |
| 1차 평가 | Private 리더보드 **상위 15팀**이 2차 진출 | 24항목 양성 Macro F1 개선. 계산은 [data D5](data.md). 평가셋은 24항목 모두 양성이 있고 제외·대체값 처리가 없다 — 전부 0인 항목은 F1 0([qna S7-1](qna.md#채점)) |
| 2차 평가 | 재현 검증과 근거 문구 정성평가. **정량 80% + 정성 20%**, 최종 **상위 7팀** 수상 | 코드·라벨 생성 이력·근거 품질 확보. [rules의 2차 평가 준비](rules.md#2차-평가-준비) |
| 최종 확정 | 종료 시 Private 순위만으로 수상 확정 아님. 재현 불가 시 수상 취소 가능 | 제공·제출 자료만으로 재현하고 출처 명시 |

근거 e1~e24는 리더보드 점수에 포함되지 않지만 제출 원본이 보존되어 2차 평가에 사용됩니다.
따라서 점수 개선과 근거 품질을 함께 관리합니다. 세부 정성 채점표와 최종 제출 양식은 제공 자료에 없으며 진출팀 별도 안내 대상입니다.

## E3. 제출 운영

| 항목 | 실행 기준 |
| --- | --- |
| 제출물 | `submit.zip` 업로드. Python 추론 코드 `script.py`, `requirements.txt`, 필요한 정적 자산으로 구성. 패키지 구조는 [design](design.md) |
| 실행 | 서버가 비공개 평가 입력에 대해 코드를 자동 실행. 경로·출력·오프라인 실행은 [data D6](data.md#d6-실행과-오류-대응) |
| 제한 | 하루 최대 1회, 제공 명세에 ZIP 2GB·실행 최대 2시간 안내. [rules R16·R21](rules.md)와 제출 전 게이트 적용 |
| 대기 | 실행 시간 외 대기열로 수 시간이 더 걸릴 수 있음. 결과 미표시만으로 실패 판정하지 않음. 완료되면 리더보드 자동 반영 |
| 마감 | 채점 지연을 고려해 여유를 두고 제출. 일정 자료는 [roadmap](roadmap.md), 확정 운영 변경은 공식 공지로 갱신 |
| 오류 횟수 | 공식 평가 탭 확인: 설치 오류 미차감, script.py 실행 이후 제출 오류 차감. 상세 환경은 [T1 확인 기록](tasks/t1-baseline.md#공식-운영-확인-2026-09-16) |

시작 순서: [루트 README의 mock](../README.md#지금-실행-가능한-명령) → dev 자가 채점·프롬프트/후처리 개선 → 자가 라벨로 검증셋·사례집 확장 → ZIP 검증·제출.
팀의 실행 단위와 선행 조건은 [tasks](tasks.md)를 따릅니다.
해설·RAG 변형 노트북은 코드 공유 게시판에 제공되었고 이 저장소 루트에도 두 베이스라인 노트북이 있습니다.
