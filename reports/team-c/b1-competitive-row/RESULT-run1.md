## 4. 왜 안 열렸나 — 사정권 4건이 모두 검증된 행을 냈다

이 관측의 사정권은 `039`·`040`·`041`·`044` 였다(요청서 §4 기준 1 근거).
**네 건 전부 제공 목록 안의 행을 지목했다.**

**`unknown` 게이트가 이 넷에서 발동할 수 없다.** 코드는 "지목한 행이 제공 목록 안에
있는가" 만 보는데, 넷 다 **있다**. 설계대로 작동했고 그 결과가 "거르지 않는다" 였다.

### 관측 자체는 성공했다 — 모델이 지어내지 않았다

| | 건수 |
| --- | ---: |
| `scope=competitive` | **79** (기준 78) |
| └ `competitive_row` 가 null 이 아님 | **72** |
| &nbsp;&nbsp;└ **제공 목록 안** | **72** |
| &nbsp;&nbsp;└ 목록 밖(지어냄) | **0** |
| └ `competitive_row = null` → `unknown` 게이트 발동 | **7** |

요청서 §5 가 "모델이 공고 본문이나 메타의 코드를 베껴 오면 이 관측은 무효다" 라고
적었는데 **그런 일은 없었다.** 지어낸 번호 0건이다.

**그러나 `scope` 분포가 거의 안 움직였다** — competitive 78 → **79**, general 122 → 120,
unknown 0 → 1. 근거를 요구받자 모델은 **서비스보조목록의 실재 행을 근거로 대며
`competitive` 를 유지했다.**

요청서 §6 이 미리 적은 실패 방식의 첫 줄이 이것이다.

> 모델이 아무 행이나 지목해 `competitive` 를 유지 → **반려. 근거 요구가 작동하지 않는다.**

정확히는 "아무 행"이 아니라 **제공 목록에 실재하는 행**이었다. 그래서 코드 쪽 방어막은
통과하고, 회복도 일어나지 않았다.
