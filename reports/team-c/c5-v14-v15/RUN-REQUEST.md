# A 실행 요청 — v14 · v15 진단 회차

요청자 C · 2026-09-18 · 승인됨(A) · **아직 실행되지 않았다**

**이 회차는 제출 후보를 만들지 않는다.** 서버 시간 예산(여유 1,008초)과 무관한 별도 진단이며
`script.py`·`submission.csv` 를 바꾸지 않는다.

## 1. 노트북에서 바꿀 것 — 한 줄이다

`notebooks/colab-baseline.ipynb` **셀 18**:

```python
DIAGNOSE_ITEMS = "v14,v15"   # 지금은 ""
```

**그 밖에는 아무것도 바꾸지 않는다.**

| 스위치 | 값 | 이유 |
| --- | --- | --- |
| `DIAGNOSE_ITEMS` | `"v14,v15"` | 이번 회차의 유일한 변경 |
| `DIAGNOSE_IDS` | `""` (그대로) | dev 200건 전체 |
| `RUN_DIAGNOSTIC` | `False` (그대로) | dev 재실행은 이 회차에 필요 없다 — 모델 로드 포함 15분이 더 든다 |

셀이 만드는 명령은 이렇다. 손으로 칠 필요는 없다.

```bash
python -X utf8 tools/diagnose_items.py \
  --items v14,v15 --ids "" \
  --labels open/dev_labels.csv \
  --model-dir <MODEL_DIR> \
  --output-dir <RESULTS>/diagnose
```

## 2. 회차 ①·②·③ 과 섞지 않는다

**한 회차에 한 변수다.**

| | 이 회차에 넣나 | 왜 |
| --- | --- | --- |
| 회차 ① 근거문구 null 해제 diff | **아니오** | `script.py` 변경이고 B 판단 대기다. 이 회차는 `script.py` 를 읽기만 한다 |
| 회차 ② 출력 4칸 | **아니오** | 별도 변수 |
| 회차 ③ 3항목 별도 호출 | **아니오** | 채택 후보가 아니다 |
| `--products` (경쟁제품 카탈로그) | **아니오** | 내 `diagnose-inject-products.diff` 는 아직 `tools/` 에 안 들어갔고, 넣으면 이 회차의 변수가 둘이 된다 |

`--products` 는 v14·v15 의 적용 대상 가르기(경쟁제품 제외)에 쓸모가 있을 수 있지만,
**기준선을 먼저 잡는다.** 이 두 항목은 별도로 물어본 적이 한 번도 없다.

## 3. 예상 비용

같은 도구·같은 200건의 3항목 회차 실측이 근거다.

| 회차 | 항목 수 | 소요 |
| --- | ---: | ---: |
| `colab-1789658250172468461` | 3 | 407.9초 |
| `colab-1789695980726180378` | 3 | 392.3초 |
| **이번 (v14,v15)** | **2** | **400초 안팎으로 추정. 모델 로드는 별도** |

2항목이라 출력 토큰이 줄지만 **입력이 지배적이라 크게 줄지 않는다.**
mock 실측 프롬프트 토큰은 최소 2,369 / 중앙 7,577 / 최대 9,101 이고 **문서 축소 0건**이다
(`MockRunner` 의 `len//2` 근사 — 실제 토크나이저 값은 회차가 알려 준다).
`MAX_MODEL_LEN` 16,384 · `MAX_TOKENS` 2,048 이므로 여유가 있다.

## 4. 받을 것

`results/diagnose/` 두 파일이면 된다.

- `items.jsonl` — 한 공고 한 줄. `요구사항`·`공고_인용`·`막힌_단계`·`판정` 과 `truth`
- `manifest.json` — `stages` 히스토그램, `elapsed_seconds`, `script_sha256`, `prompt_sha256`

`--labels` 를 주므로 각 줄에 정답이 붙는다. **원응답(`--debug-responses`)은 필요 없다.**

## 5. 받으면 내가 할 것 — 도구는 이미 준비됐다


이 스크립트는 **기존 회차 두 개로 이미 검증했다.** 느슨 회차의 v16 6/139/0 → 6/39/0,
보수 회차의 1/29/5 → 1/17/5 를 그대로 재현하고, 옛 회차의 `판정`·`막힌_단계` 어긋남
116건을 경고로 띄운다. 손으로 세지 않는다.

회차 등록은 `tools/register_run.py`, 제출 CSV 가 생기는 회차가 아니므로
`compare_runs.py` 대조 대상은 없다.

## 6. 이 회차가 답하는 것 / 답하지 않는 것

**답하는 것.**

1. v14·v15 를 별도로 물으면 TP 가 나오나. 제출 파이프라인은 이 두 항목에서 FN 8·6 이다.
2. **놓친 양성이 어느 단계에서 막히나.** 이것이 이 회차의 핵심이다 —
   `context_not_observed` 면 참가자격 문구를 못 본 것이고, `condition_not_met` 면
   보고도 금액 구간·기업 범위를 잘못 맞춘 것이다. **처방이 갈린다.**
   앞 회차에서 v16 은 FN 5건이 전부 `context_not_observed`, v18 은 전부
   `condition_not_met` 이었다. 같은 처방을 쓰면 안 되는 사례가 이미 있다.
3. [조건표](README.md)의 금액 구간이 이 항목에서도 TP 를 안 지우나.

**답하지 않는 것.**

- **제출 점수.** 별도 질의는 제출 파이프라인이 아니다. 두 회차의 값이 4배 가까이 달랐다.
- **게이트 채택 근거.** 구간은 양성을 지우는 방향으로만 작동해 FN 8·6 을 고치지 못한다.
- 전체 Macro F1. 0.003 이하는 회차 잡음이다.

## 7. 증거 수준

지금까지는 **CPU 준비만이다.** mock 실행·스크립트 검증·조건표는 전부 모델을 부르지 않았다.
이 회차가 돌면 **실제 GPU 회차**가 되며, 그것도 대회 서버 성공과는 다른 사건이다.
