# C — 무라벨 발화 배율 (v10~v18 · v20)

담당 C · 2026-09-23 · **CPU 집계와 재생. 모델 호출 0회 · GPU 0초. 규칙을 만들지 않았다.**

세션 내내 C 후보의 채택을 막아 온 미확인 사항 하나를 닫는다 —
**"이 규칙이 dev 밖에서 얼마나 터지나."**

## 0. 결론

**열 항목을 한 번에 훑었으므로 동시 기준으로 읽는다. 그러면 `v14` 하나만 남는다.**

| 동시 95% 에서 정해진 것 | 항목 |
| --- | --- |
| **무라벨에서 더 적게 터진다** | **v14** `[0.09, 0.78]` |
| 더 많이 터진다 | **없다** |
| 미정 (구간이 1 을 문다) | 나머지 아홉 |

점추정만 보면 v18 2.87 · v20 1.54 · v13 1.45 가 "dev 밖에서 더 자주 터진다" 로 읽힌다.
**그렇게 읽으면 안 된다.** 저 셋의 dev 발화가 각각 3 · 5 · 11 건뿐이라 구간이 전부 1 을
문다(v18 명목 `[0.92, 8.98]`). **분모가 없어서 생긴 큰 수를 신호로 승격하지 않는다.**

`v15` `[0.07, 1.26]` 과 `v16` `[0.11, 1.42]` 는 **항목별 명목 구간에서만** 상한이 1 아래이고
동시 기준에서는 아니다. **탐색적 관측으로만 적는다.**

`v14` 는 C 항목 중 F1 이 가장 높다(0.824). `.wiki/plan-active.md` 가 A4 의 v23 배율 0.05 를
두고 적은 경고 — dev 에 맞춘 규칙의 신호 — 와 같은 모양이다.
**다만 배율만으로 반려하지 않는다(W5). 보고 대상이다.**

### 0-0. 왜 동시 기준인가

이 표는 **가설 하나를 미리 정해 놓고 확인한 것이 아니다.** 열 항목을 한꺼번에 재고
그중 튀는 것을 골랐다. 그러면 항목마다 5% 씩 헛발할 여지가 쌓여, 열 개를 훑으면
**아무 신호가 없어도 하나쯤 "정해진 것"이 나오는 게 정상**이다.

그래서 Bonferroni 로 항목마다 0.05/10 을 쓴다(z 1.9600 → **2.8070**). 이래야
"열 중 어느 하나라도 헛발" 확률이 5% 다. 표는 두 구간을 다 싣고, **결론은 동시 쪽으로 읽는다.**

### 0-1. 첫 판이 v12 를 틀리게 확정했다

리뷰 [P1]. 처음 낸 판은 v12 를 `[0.14, 0.90]` 으로 적고 **"더 적다"** 로 확정했다.
**그 구간이 틀렸다.** dev 쪽 불확실성만 넣고 무라벨 쪽을 뺐기 때문이다.

무라벨 분모가 열 배(2,000)라고 해서 그쪽 **분자**가 확실한 것은 아니다. v12 는 무라벨
발화가 **14건뿐**이라 그 항이 구간을 크게 넓힌다. 양쪽을 같이 넣으면 **`[0.12, 1.05]` —
1 을 문다.**

더 나쁜 것은 내가 그 생략을 **알면서 여유가 있다고 단정한 것**이다. 첫 판 §3 이
*"넣으면 구간은 더 넓어지므로 '미정' 판정은 뒤집히지 않고 '더 적다' 넷만 다시 봐야 한다.
그 넷은 상한이 0.50~0.90 이라 여유가 있다"* 라고 적었다. **재지 않고 여유를 주장했고,
재 보니 넷 중 하나가 뒤집혔다.** 방향을 못 정하는 구간을 확정으로 기록한 것이다.

이제 두 쪽을 다 넣은 **Katz 로그법 비율비 구간**을 쓴다. v17 도 `[0.31, 1.07]` 로
상한이 1 을 넘고, v16 은 `[0.17, 0.97]` 로 간신히 남는다.

### 0-2. 두 번째로도 같은 실수를 했다 — 열 항목을 훑고 항목별 기준으로 읽었다

리뷰 [P1] 라운드 2. 위를 고친 뒤에도 **다중비교를 안 넣었다.** 열 항목을 한 번에 재고
그중 상한이 1 아래인 것을 골라 놓고, 기준은 **항목 하나짜리 명목 95%** 를 썼다.

| | 정해진 것 |
| --- | --- |
| 명목 95% (라운드 1) | v14 · v15 · v16 — **셋** |
| **동시 95% Bonferroni (지금)** | **v14 — 하나** |

`v15` 는 `[0.11, 0.82]` → `[0.07, 1.26]`, `v16` 은 `[0.17, 0.97]` → `[0.11, 1.42]` 로
**둘 다 1 을 문다.** 리뷰가 Fisher 양측 + Holm 으로 따로 확인한 결과도 v14 하나였다.

**두 라운드가 같은 모양이다** — 재지 않은 불확실성을 결론에 안 넣었다. 첫 번째는 표본
한쪽을, 두 번째는 항목 여럿을 훑었다는 사실을 뺐다. 이번에는 두 구간을 다 실어
어느 기준으로 읽는지 표에 박아 뒀다.

## 4. 이것이 바꾸는 것과 안 바꾸는 것

### 바꾸는 것

- **A 후보(v16·v18 완전관측 게이트)의 미확인 사항 하나가 닫혔다.** `reports/team-c/a-v18-notice-complete/README.md`
  §8 이 "무라벨 배율을 못 쟀다" 로 남겨 둔 자리다. 이제 **v16 은 배율 0.40 · 동시 구간
  `[0.11, 1.42]` 로 방향 미정**이라고 적을 수 있다. 수를 못 쟀던 자리에 수가 생겼을 뿐
  **방향은 여전히 안 정해진다.** **그 후보의 반려 사유는 안 바뀐다** — 반려는
  `docs/data.md:48` 계약 충돌이 단독으로 낸 것이고, 배율은 셋째 사유였다.
- **v14 를 건드리는 앞으로의 후보는 배율 상한이 1 아래인 구간에서 작업한다는 것을 알고
  시작한다.** 그 사실을 아는 것과 결과를 예측하는 것은 다르다 — §4-1 을 본다.
  v15·v16 은 명목에서만 낮고 동시에서는 미정이라 이 문장에 넣지 않는다.

### 4-1. 이 표로 서버 점수를 예측하지 않는다

리뷰 [P2]. 첫 판은 이 자리에 *"dev 이득이 서버로 갈 확률이 구조적으로 낮은 자리다"*
라고 적었다. **그렇게 단정할 근거가 이 자료에 없다.** 지웠다.

무엇이 없는지 그대로 적는다.

- **발화율은 정확도가 아니다.** 규칙이 dev 밖에서 덜 터진다는 것은 그 규칙이 dev 밖에서
  **덜 맞는다**는 뜻도 **덜 틀린다**는 뜻도 아니다. 무라벨에 라벨이 없어 둘 다 못 잰다.
- **dev→서버 전이에 고정 계수가 없다.** 다섯 쌍의 실측이
  0.005 · 0.249 · 0.926 · −0.147 · −0.041 이다. 곱할 수가 없다.
- **배율과 서버 결과를 이어 본 관측이 하나뿐이다.** A4 의 v23 이 배율 0.05 였고 그 묶음이
  서버에서 −0.0026 이었다. **한 점이고, 그 제출은 v6·v9·v23 을 함께 올려 v23 단독 효과가
  미측정이다**(계획 문서 §"정해지지 않은 것"). 한 점으로 함수를 그리지 않는다.
- `docs/workflow.md` W5 는 **"배율만으로 자동 반려하지 않고 반드시 보고한다"** 로 정한다.
  이 표는 **보고**지 판정이 아니다.

낮은 배율이 말하는 것은 하나뿐이다 — **그 규칙이 손대는 공고가 dev 밖에 드물다.**
그래서 **이득도 손해도 dev 에서 본 것보다 작게 나타날 여지가 있다**는 정도이고,
어느 쪽으로 얼마인지는 **서버에 올려야 안다.**

### 안 바꾸는 것

- **v18·v20 을 다시 여는 근거가 되지 않는다.** 계획서가 "새 재료 없이 다시 열지 않는다" 로
  닫은 것을 이 표는 못 연다 — 그 둘이 바로 구간이 1 을 무는 "미정" 이다.
- **어떤 후보의 채택·반려도 이 표로 결정하지 않는다.** 발화율은 정탐률이 아니다.
  #95 가 정한 삭제형 후보의 임계 `q < F/2` 는 **라벨이 있어야** 쓸 수 있고, 라벨은 아직 없다.

## 5. 산술과 실측

후보를 만들지 않았으므로 **TP/FP/FN 전→후가 없고 대상 밖 바뀐 셀도 없다**(0셀).
표의 dev TP/FP 는 비교용으로 같이 센 것이고 이 티켓이 움직인 값이 아니다.

| | 무엇 |
| --- | --- |
| **실측** | §3 의 발화 수·발화율·배율·구간 전부. 두 CSV 에서 직접 센 값이다 |
| **산술** | §7 의 "6,000건이어도 동시 기준에서는 하나도 안 닫힌다" 하나. **같은 발화율이 유지된다는 가정**을 깐 계산이고 그 회차를 돌려 본 것이 아니다 |

**서버 점수에 대한 산술은 하지 않았다.** 이유는 §4-1 에 있다.

## 6. 증거 수준

**CPU 집계 + 저장 응답 재생.** 모델 호출 **0회** · GPU **0초** · 제출 CSV 미생성.
무라벨 쪽 발화는 **실제 GPU 회차**(`58af667`, 다른 담당이 돌린 것)의 산출물을 읽은 것이고
이 티켓이 돌린 회차가 아니다. 대회 서버와 무관하다.

## 7. 미확인 사항

- **무라벨 2,000건이 서버 분포를 대표하나.** `ids.txt` seed 20260923 추첨이라 무라벨 안에서는
  무작위지만, 무라벨 집합 자체가 서버 채점 집합과 같은 분포인지는 확인하지 않았다.
- **미정 아홉의 방향.** 무라벨을 6,000건으로 늘려도 **동시 기준에서는 하나도 안 닫힌다**
  (같은 발화율 가정). 가장 가까운 `v15` 가 `[0.08, 1.11]` 이다. 명목 기준으로 봐도
  `v12` 하나뿐이다(`[0.13, 0.97]`). **dev 쪽 분모가 200 에 묶여 있어서다** —
  무라벨을 아무리 늘려도 `1/dev_k` 항이 안 줄어든다.
  이건 산술 예측이고 실측이 아니다. 아홉을 가르려면 dev 가 커지거나 라벨이 열려야 한다.
- **발화한 무라벨 셀의 내용.** 한 건도 열어 보지 않았다. 열면 dev 로 규칙을 고르는 것과 같은
  과적합 경로가 되므로 이 티켓에서는 일부러 안 했다.
- **v10 0.92 · v13 1.45 가 왜 다른가.** 둘 다 dev FP 8 인데 배율의 점추정이 갈린다. 원인을 안 봤다.
- **회차 간 churn.** 구간은 같은 규칙을 같은 크기의 **다른 표본**에 돌렸을 때의 흔들림만
  담는다. **같은 표본에 같은 코드를 두 번 돌렸을 때의 흔들림은 안 담는다** — 무라벨을
  두 번 돌린 회차가 없어 못 쟀다.
