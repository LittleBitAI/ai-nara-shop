## 3. 무엇을 바꿨나 — 게이트 조건 하나

운영(`script.py` 796-804)은 **문서 전체**의 전역 플래그를 본다.

```python
if qualification == "unrestricted":
    # ponytail: 전체 문서가 잘리면 부재 새 판정은 보류한다.
    complete = (rec.get("input_completeness", {}).get("완전관측") is True
                and not any((rec.get("dropped_doc_counts") or {}).values())
                and "[Truncated documents; unseen remainder]" not in visible
                and "[Missing documents]" not in visible
                and facts["qualification_complete"] == "yes")
    if not complete:
        return {}, "absence_not_observable"
```

후보는 **그 문서의 본문이 `visible` 안에 그대로 있는지**를 본다.

```python
rec.get("input_completeness", {}).get("완전관측") is True
and notices                                            # 공고문이 있어야 한다
and all(d["text"].strip() and d["text"] in visible for d in notices)
and facts.get("qualification_complete") == "yes"
```

**새 방식이 아니다.** v20 의 `software_complete`(`script.py` 737-741)가 이미 같은 모양이다 —
전역 플래그 대신 해당 문서의 전문이 보이는지를 본다. 이미 채택된 배선을 한 자리에 더 적용한 것이다.

**게이트만 바꿨다.** 통과 뒤의 우선조달 예외·금액 구간 판정은 운영 순서를 그대로 옮겼고
(`script.py` 805-822) 금액 경계·올리는 항목·예외 처리에 손대지 않았다.
운영이 `absence_not_observable` 이 **아닌** 사유를 내면 한 글자도 바꾸지 않는다(검사로 고정).

**절단을 요건 부재로 단정하지 않는다.** 공고문 자체가 없거나 비었거나 한 조각이라도
잘리면 종전대로 보류한다.

## 10. 미확인 사항

- **무라벨 발화 배율.** §7 의 이유로 이 저장소에서 못 잰다. **이것이 보류의 유일한 사유다.**

- **`132`·`195` 의 `scope=general` 이 옳은지.** 면허업종과 어긋난다는 관측뿐이고
  라벨·조문으로 어느 쪽이 맞는지 판단하지 않았다.
- **같은 ZIP 재실행 churn 위에서 이 4셀이 안정한지.** CPU 재생은 결정적이라 흔들리지
  않지만, GPU 회차에서 같은 4셀이 나오는지는 재지 않았다.
- **`22` 의 TP 가 다른 회차에서도 열리는지.** `qualification_complete=yes` 는 모델 출력이라
  회차마다 달라질 수 있다.
