## 4. churn 은 못 쟀다 — 1회차만 왔다

`RUN-CARD.md` 는 두 회차를 요구했다(N3 는 추가 호출을 늘리는 모델 앞 단계 후보라
`docs/workflow.md` W5 가 두 번째 회차를 요구한다). 받은 ZIP 은 하나다.

**그래도 판정은 선다.** 이유 둘.

- **효과가 변동폭보다 크고 방향이 한쪽이다.** 관측된 회차 변동폭은 Macro 0.034 인데
  (`reports/team-c/c-variance/`), 이번 −0.034 는 **같은 원응답 위의 재생 비교**라
  모델 흔들림이 아예 안 섞인다. 같은 모델 출력에서 코드만 갈아 낸 차이다.
- **FP +44 는 잡음으로 안 생긴다.** 45셀이 바뀌었는데 그중 44셀이 FP 증가 한 방향이다.

두 번째 회차가 답했을 것은 "이 코드의 회차 간 churn" 이고, 그것은 채택 판정에
필요하지 않다 — 채택을 막는 것은 위 두 줄과 서버 시간이다.
