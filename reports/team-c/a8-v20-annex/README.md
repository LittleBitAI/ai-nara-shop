## 착수서 대비 정정 한 건

**예산 추정의 분모가 934자가 아니라 1,568자다.** 착수서의 `934/1.5 ≈ 623토큰, 초과 0/200`은
법령 원문만 센 추정이고, 실제로 붙는 것은 지시 머리글을 포함한 1,568자다.
같은 글자 환산을 적용하면 약 1,045토큰이 되지만 **이것도 추정이며 채택하지 않는다.**
**실제 값은 아래에서 쟀다 — 586토큰.** GPU 실행기도 생성 호출 전에 같은 계산을 다시 하고
조건을 못 채우면 멈춘다.

머리글을 줄여 블록을 작게 만들 수는 있으나, 그 문장들이 "법령을 인용 근거로 쓰지 말 것 ·
null을 금액 추론으로 채우지 말 것 · 새 필드를 만들지 말 것"을 담는다. **측정 결과 줄일 필요가
없었다** — 채택한 예산에서 최악 공고에도 428토큰이 남는다.

## OFF/ON 재생은 정적 불변이다 — 유출은 스윕이 잡는다

같은 H4 원응답(`colab-1789902969401579900/dev-debug`)을 후보 문맥 OFF/ON으로 재생하면 두 CSV가
**서로 바이트 동일**하다(바뀐 셀 0, v20 1/4/4). 보관 기준선
(`a5-label-definition/head-replay/submission.csv`)과는 v13 수리 때문에 **세 셀이 일부러 다르다** —
그래서 혼합 Macro 도 0.591008188119다.

**이것을 "소비 경로 배선 검사"라고 부르지 않는다.** 후보가 소비자를 안 바꾸고 재생은 프롬프트를
읽지 않으므로 바이트는 **같을 수밖에 없다.** 이 재생이 말하는 것은 `activate()`가 재생 경로에서
읽히는 것을 하나도 건드리지 않았다는 정적 불변뿐이다. 라운드 1 리뷰의 P2 지적이 옳다.

법령 문자열이 항목으로 새는지는 **결정적 소비자 스윕**이 잡는다 — 공고 200건 × 인용 필드 7개에
별표의 실제 부분문자열을 넣고 24항목을 다시 계산한다(`LawQuotationTests`).

## 고정 회차에서 도달 가능한 v20 TP 상한은 2다

착수서의 분석을 구현 기준에서 원자료로 다시 확인했다. H4 재생의 v20은 TP `133`,
FP `056·064·068·144`, FN `24·131·132·134`다.

| FN | 차단 지점 |
| --- | --- |
| 024 · 131 · 134 | 제안요청서 1건 탈락 + 완전관측 `false`. **프롬프트가 못 바꾸는 입력 사실**이다 |
| 132 | `software_business=no`. 완전관측 `true`, 문서 탈락 없음 — 주입으로 닿을 수 있는 유일한 건 |

그래서 **TP 상한은 기존 1 + 132 한 건 = 2**다. 게이트를 풀어 이 상한을 올리지 않는다.
사전 등록 기준(§5)의 `TP≥2`는 이 계산 위에 있다. Macro 상승 하나만으로 채택하지 않는다.

  절단됐던 **`PPS-DEV-189` 한 건**이며, 두 군 모두 절단이 풀려 H4와 달라진다.
- **이 값은 파일럿 한정이다.** 이 PR 이 고친 v13 근거 구멍과 달리, 출력 예약을 운영에 채택하려면
  단계별 예약이 필요하고(baseline 출력은 max 1,055) 그것은 별건이다.
- 규칙: 출력 예약은 대회가 정한 값이 아니다. R19는 패키지 버전, R4는 정상 응답을 요구하며
  관측 최댓값의 2배 예약은 그 요건을 해치지 않는다. R21 총시간은 줄어드는 방향이다.
- 재현: 고정 리비전의 토크나이저 파일만 받아(`tokenizer*`·`*.jinja`, 가중치 없음)
  `a8_v20_annex.TokenizerRunner`로 센다. **서버 고정 `transformers` 5.14.1이 필요하다** —
  4.x는 이 모델의 `tokenizer_config.json`을 못 읽는다. torch·GPU는 필요 없다.

## 예산 검사가 GPU에서 무엇을 하나

`budget_report()`가 공고 200건마다 control/후보 두 군의 **전체 메시지**를 이 런타임의
실제 토크나이저·제출 chat template으로 센다. `조항호내용` 제외 meta, 같은 products·문서 선택·
`max_chars`·입력 예산·출력 예약량을 쓴다. 남는 기록은 `budget.json`이다.

- 두 군 공통 예산 15,296으로 센다. 운영값(14,272)과의 차이도 같은 파일에 남긴다.
- 통과 조건: **추가 축소 0/200**과 **두 군 공고 본문 sha256 동일**.
- control에 이미 있던 절단은 `control_truncated`로 따로 센다. 공통 예산을 더 줄이지 않는다.
- 한 건이라도 추가 축소되면 **생성 호출 전에** 멈추고 `budget.json`만 남긴다.
- `token_count_kind != actual`이면 조건을 채워도 `budget_safety_evidence`는 거짓이다.
  mock·글자 환산은 예산 근거가 아니다.

## 이웃 실험의 실측이 기대값을 낮춘다

`main` 에 머지된 [wiki RAG 파일럿](../../wiki-rag-pilot/results.md)이 같은 v20 을 세 군으로
이미 돌렸다 — **두 회차 1,200회 호출에서 검증된 참여 조항 인용 0건**이고, 나온 인용 1건은
원문에 없는 문장이었다. 그 `raw` 군은 지침 제2~4조와 별표 1 을 포함한 4,505자를
**user 메시지**에 넣었다. A8 은 제2조+별표 1 만 **system 프롬프트**에 붙이므로 같은 실험은
아니지만, **법령 원문을 넣는 것만으로 v20 이 움직이지 않았다는 실측**이 하나 생겼다.
두 회차를 돌릴 때 이 사실을 알고 시작하며, 효과가 없으면 그것도 같은 방향의 근거로 기록한다.

## 회차가 무엇을 남기나 — 관측과 감사

두 회차를 돌려도 **무엇을 볼지**가 없으면 Macro 두 숫자만 남는다. 그래서 회차 자체가
자기 근거를 남기게 했다. 계약은 [observation-contract.json](observation-contract.json)이 소유한다.

- **관측**: `observe_chat()`이 실행기의 `chat`을 인스턴스 속성으로만 감싸 실제 모델 요청을
  `diagnostics.jsonl` 한 파일에 기록한다. 루트·군·청크·호출·파싱이 순서대로 들어가고,
  호출 하나는 `(run_id, episode, arm, sample, phase, chunk_start, call_seq, call_index)`로 유일하다.
  분할 재시도는 system이 바뀐 **다른 요청**으로 남는다. **추론은 바뀌지 않는다** —
  감싸기는 `finally`에서 풀리고, 원래 `chat`이 인스턴스에 없었으면 지운다.
- **왜 필요했나**: 파일럿의 군별 로그는 `run_started`가 없어 사이드카가 **모든 이벤트를 버렸다**
  (400 이벤트 → 0 span). 지금은 1,618 이벤트 → 1,618 op, 생성 키 400개가 모두 구별되고
  열고 닫힌 쌍이 408개다. 이 확인은 **CPU 재생 로그**로 했고 Langfuse UI 적재는 미실행이다.
- **감사**: 회차가 끝나면 같은 런타임에서 `a8_v20_audit.py`가 저장된 원응답만 읽어
  인용 상태(null/빈값/정확/공백복원/원문없음)와 실제 `verify_company_size` 판정을 갈라
  `v20-audit.json`을 만든다. **모델을 다시 부르지 않는다.**
- **먼저 볼 숫자**: 바뀐 공고의 `gain_kind`다. 이것은 **실제 v20 전이**로 판정한다.

  | 값 | 뜻 |
  | --- | --- |
  | `verified_absence` | 적용 가능한 공고에서 참여 인용이 **없어서** 부재 위반을 새로 썼다(`write_1`). **v20은 부재탐지 항목이라 이쪽이 주 기전이다** |
  | `verified_quote` | 적용 가능하고 검증된 인용으로 `write_0`으로 갔다 |
  | `fallback_only` | `write`가 `preserve`로 내려앉았다. **원인을 묻지 않는다** — 인용 기각이든 문서 완전성이든 결과는 같고, 원인은 `fields`가 들고 있다. **기전이 아니다** |
  | `other` | 나머지. 이름을 안 붙이는 것이 잘못 붙이는 것보다 낫다 |

  인용 상태만 보면 판정이 안 움직인 변화와 v20이 열리지도 않는 공고의 정확한 인용이
  기전으로 샜다(라운드 1 P1). 부재 기전을 `other`로 두면 **먼저 볼 숫자가 기전을 놓친다**
  (라운드 2 P1). H4 기준선이 정확히 fallback 모양이다 — 참여 인용 200건 전부 null,
  v20 양성 5건 전부 부재 분기. 그것이 이 실험의 **실패 분모**다.
- **프롬프트 전문은 기본적으로 안 나간다.** `capture_protocol=1` 로그에는 실제 프롬프트가
  들어 있어서, 사이드카는 `--include-prompts`와 `--dev-input`이 있고 **provider를 만들기 전**
  검사가 통과할 때만 본문을 싣는다 — 보낼 곳이 대회 전용 로컬 주소 그대로이고, 로그가
  고정 공개 dev 회차이고, **실린 본문이 실제 dev 파일에서 재구성한 것과 한 글자까지 같고**,
  신원 미확정 본문이 0건일 때다. 막으면 `prompt_capture="withheld"`로 남긴다.
  **공고 id가 고정 dev에 있다는 것은 본문이 dev에서 왔다는 근거가 아니다**(라운드 2 P0) —
  유효한 id에 임의 문자열을 붙인 로그가 그 검사만으로는 통과했다.
  전송도 그 호스트에 묶는다 — `requests`는 기본적으로 redirect를 따라가므로 로컬
  엔드포인트가 307로 외부를 가리키면 검사를 통과한 본문이 다시 나갔다(라운드 2 P0).
  예외 메시지와 traceback도 본문으로 취급한다 — 개인 절대경로가 들어 있다(라운드 2 P0, R17).

## 실행하지 않은 것

실제 모델 호출, GPU 두 회차, 후보 시간, 무라벨 6,000건 발화율, 서버 제출.
예산은 CPU에서 확정됐지만 **모델이 블록을 어떻게 쓰는지는 여전히 미측정**이다.
Langfuse 로컬 스택 적재·UI 확인, API 표본(Q1 차단), 사람 의미 검토도 미실행이다.
v13 수리까지의 독립 리뷰는 **라운드 7의 `머지 허용`**으로 끝났고 PR #84로 머지됐다.
관측·감사 배선은 **PR #87의 아홉 라운드에서 P0 스물셋·P1 열·P2 셋**을 받아 전부 고쳤다.

| 라운드 | 무엇이 나왔나 |
| --- | --- |
| 1 | 수출 경계 미구현(P0), `schema_sha256`·`payload_sha256`·`gain_kind`·루트 mode |
| 2 | 그 수출 경계의 **세 갈래 우회** — 본문 출처 미검증·redirect·자유 텍스트. `gain_kind`가 놓친 부재 기전 |
| 3 | 또 **세 갈래** — 메시지 형태·환경 프록시·세션 경로. set 순서 때문에 **진짜 회차가 거부되는** 결함과 보류 원인 열거 |
| 4 | 응답 결속(본문 없는 시작에 붙은 output)과 **구조화 필드 위생** — `settings.note`·`items`의 임의 문자열 |
| 5 | span 이름·`usage_details`·중첩 키, 그리고 **위생이 진짜 값을 지움** + 실제 로그에서 크래시 |
| 6 | 통로 **밖에서 직접 쓰는 자리**, `_fixed()` 계약 위반, 평문 기본, `set()` 크래시, `split` 유실 |
| 7 | map **키**, 패턴 기반 평문 예외(`phase`·`error_type`·버전). **P1 없음** — 둘이 같은 원리다 |
| 8 | 남은 **모양 예외 네 자리** — 자산 키·자기 선언 `dev_ids`·버전 모양·span 이름의 원본 값. **P1 없음** |
| 9 | **hash 가 마지막 모양 예외였다** — 재계산 대조로 바꿨다. 생산자가 직접 쓰는 오류형 누락(P1). **둘로 절반** |

**같은 자리를 다섯 라운드 연속 뚫렸고, 라운드 5에서 접근을 바꿨다.** P0 열둘이 전부 같은
질문의 다른 면이었다 — 값이 span으로 나가는 경로가 어디까지인가. 매 라운드 지적된 출구에
게이트를 달았으니 열거에서 빠진 면이 다음에 나왔다. 하나 고치면 둘 생긴 것이 아니라
**처음부터 면이 N개였고 매 라운드 두세 개만 닫은 것이다.**

지금은 `plan()`이 돌려주는 **모든 Op가 `guard()` 하나를 지난다.** 기준도 추측에서 실측으로
바꿨고(실행기 클래스·실제 H4 로그), 검사는 **실제 회차 로그 1,020 이벤트**로
크래시·보존·차단 셋을 같이 본다 — 손으로 쓴 이벤트로는 라운드 5의 결함 셋을 하나도
못 잡았다. 규칙은 허브 위키 `craft/gate-the-exit-not-the-callers`가 소유한다.

가드를 하나씩 되돌려 확인했고 **mutation이 네 번 초록이었다** — 그때마다 검사가 약한
자리였다(system 검사가 user 위조를 가렸고, 함수만 보고 배선을 안 봤고, 다른 가드가
가려 단독 검사가 없었다). 결과는 `artifacts/review/`.
`open/train_unlabeled.jsonl`은 이 워크트리에 없어 h3 파일럿 검사 1건이 실패한다 —
A8 경로와 무관한 기존 상태다. 무라벨 수집 분기는 유망 판정 전까지 만들지 않았다.

dev 전체 GPU 최고 0.599316(`18f07e5`), 서버 최고 0.508414·6,380초는 그대로다.
