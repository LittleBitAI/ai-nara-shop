## 4. 새 가설 C7 — 역할과 값이 싸우면 역할을 믿는다

### 무엇을 봤나

운영 코드가 `qualification_role` 로 `qualification` 을 검증한다.

```python
allowed = ("small_only", "sme_allowed") if role == "eligibility" else (
    ("unrestricted",) if role in ("checklist", "legal_reference", "none") else ())
if facts.get("qualification") not in allowed:
    facts["qualification"] = "unknown"
```

역할이 "참가자격 조항이 아니다"(`checklist`·`legal_reference`·`none`)라고 말하면
`unrestricted` 만 받고, 그 자리에 `sme_allowed` 가 오면 **값을 버려 `unknown` 으로 둔다.**

**그 처리가 비대칭이다.** 역할이 이미 "제한 조항이 아니다"라고 말했다면 제한은 없는
것이다. 모른다고 둘 일이 아니라 `unrestricted` 로 읽을 일이다. 운영 코드가 그 역할에서
`unrestricted` 만 허용하는 것 자체가 "이 역할이면 제한이 아니다"를 이미 인정한다.

### 적용 범위 — dev 200건에서 2건

| role × qualification | 건수 |
| --- | ---: |
| `eligibility` × `sme_allowed` | 78 |
| `eligibility` × `small_only` | 67 |
| `checklist` × `unrestricted` | 30 |
| `none` × `unrestricted` | 13 |
| `none` × `unknown` | 5 |
| `legal_reference` × `unrestricted` | 3 |
| **`checklist` × `sme_allowed`** | **2** ← 어긋나는 전부 |
| `checklist` × `unknown` · `legal_reference` × `unknown` | 1 · 1 |

어긋나는 2건(`038`·`044`)은 **둘 다 라벨이 v18 이고 둘 다 지금 아무것도 못 잡는다.**
