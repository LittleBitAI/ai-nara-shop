## 4. 새 가설 C7 — 역할과 값이 싸우면 역할을 믿는다

### 무엇을 봤나

운영 코드가 `qualification_role` 로 `qualification` 을 검증한다.

```python
allowed = ("small_only", "sme_allowed") if role == "eligibility" else (
    ("unrestricted",) if role in ("checklist", "legal_reference", "none") else ())
if facts.get("qualification") not in allowed:
    facts["qualification"] = "unknown"
```

역할이 "참가자격 조항이 아니다"(`checklist`·`legal_reference`·`none`)라고 말하면
`unrestricted` 만 받고, 그 자리에 `sme_allowed` 가 오면 **값을 버려 `unknown` 으로 둔다.**

**그 처리가 비대칭이다.** 역할이 이미 "제한 조항이 아니다"라고 말했다면 제한은 없는
것이다. 모른다고 둘 일이 아니라 `unrestricted` 로 읽을 일이다. 운영 코드가 그 역할에서
`unrestricted` 만 허용하는 것 자체가 "이 역할이면 제한이 아니다"를 이미 인정한다.

### 적용 범위 — dev 200건에서 2건

| role × qualification | 건수 |
| --- | ---: |
| `eligibility` × `sme_allowed` | 78 |
| `eligibility` × `small_only` | 67 |
| `checklist` × `unrestricted` | 30 |
| `none` × `unrestricted` | 13 |
| `none` × `unknown` | 5 |
| `legal_reference` × `unrestricted` | 3 |
| **`checklist` × `sme_allowed`** | **2** ← 어긋나는 전부 |
| `checklist` × `unknown` · `legal_reference` × `unknown` | 1 · 1 |

어긋나는 2건(`038`·`044`)은 **둘 다 라벨이 v18 이고 둘 다 지금 아무것도 못 잡는다.**

### 실측 — 재기 전에 예측을 적고 쟀다

**예측**: v18 TP 3→5 · FN 4→2 · 바뀐 셀 2 · FP 유지.
**실측**: v18 TP 3→**4** · FN 4→**3** · 바뀐 셀 **1**(`044`) · FP 2 유지.

```
Macro  0.793712449043 → 0.798520141351  (+0.004807692308)
바뀐 셀 1 · 대상 밖 0셀 · TP 줄어든 항목 없음
v18  3/2/4 → 4/2/3   F1 0.500000 → 0.615385
```

**예측이 절반 빗나갔다.** `038` 은 역할을 적용해도 안 잡힌다 — 막히는 자리가
`unverified_qualification` 에서 **`unverified_priority_exception`** 으로 한 칸 옮겨갈 뿐이다.
`priority_exception=unknown` 이라 우선구매 예외를 모르는 상태이고, 그것은 이 가설의
범위 밖이다(§5 가 이어받는다).

### 어떻게 읽나

- **효과가 작다.** +0.0048 은 관측된 회차 변동폭(0.034)보다 훨씬 작다. 다만 이 수는
  **같은 원응답 위의 재생**이라 모델 흔들림이 안 섞인 결정적 비교다.
- **표본이 1건이다.** 근거가 조문이 아니라 운영 코드의 일관성이고, 그 일관성이 옳다는
  것을 dev 한 건 말고는 확인할 자료가 없다. **dev 라벨 기반에 가깝다.**
- **FP 위험은 낮다.** 적용 대상 자체가 2건이고 둘 다 라벨이 양성이다. 무라벨에서

## 5. 새 가설 C8 — scope 인용도 skeleton 대조로 살린다

#142 가 v13 의 인용 검증에 `skeleton_quoted()` 를 들였다. PDF 추출이 숫자·괄호를 다른
줄로 밀어 놓으면 원문 대조가 실패하는데, 그 문자를 지운 뼈대로 맞춰 **문서 자신의 글자**를
돌려준다. 그 도구가 `scope_quote` 에는 안 쓰인다.

### 왜 이 자리인가

`unverified_scope` 는 dev 에서 **11건**이고 기업규모 판정을 통째로 접는다. 그 11건의
인용을 하나씩 대조했다.

| | 건수 | 무엇 |
| --- | ---: | --- |
| skeleton 으로 **살아난다** | **1** | `041` — v18 양성을 놓치고 있었다 |
| skeleton 으로도 안 산다 | 10 | 인용이 `컴퓨터서버[4321150102]` · `잡석[1111169701]` 처럼 **품명과 품목번호**다 |

살지 않는 10건은 인용 복원 문제가 아니다. 모델이 원문 문장 대신 메타데이터에서 조합한
문자열을 적었고, 그것은 다른 자리다(§6).

### 실측 — 예측이 또 절반 빗나갔다

**예측**: `041` 하나가 바뀌어 v18 TP 3→4 · 대상 밖 0셀.
**실측**: v18 TP 3→4 는 맞았지만 **바뀐 셀이 3개**다.

```
Macro  0.793712449043 → 0.795898953987  (+0.002186504944)
바뀐 셀 3 — (041, v10) · (041, v11) · (041, v18)
v10  4/6/3 → 4/7/3   F1 0.470588 → 0.444444
v11  5/5/1 → 5/6/1   F1 0.625000 → 0.588235

```

**연쇄 효과를 안 봤다.** `041` 의 scope 가 검증되자 `verify_document_requirements()` 의
v10 조건(`scope == "competitive"` + 인용 검증)이 함께 통과해 v10 이 올라가고, 운영의
C6-3 이 그 위에 v11 을 올린다. 둘 다 그 공고에서는 오탐이다.

순효과는 **+0.002187** 로 양수이고 TP 손실 0 · 대상 밖 0셀이지만, **v18 하나를 얻으려고
