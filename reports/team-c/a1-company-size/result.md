## 결정표와 제공 조문

다음 표는 일반 물품·일반 용역, 별도 특례 없음, 사실 확인 완료에 한한다.

### 예외는 어느 칸에 적용하는가

- 제2조의3의 명시적 우선조달 예외는 제한 없음 칸의 v16·v18을 면제한다.
  법령 이름만 인용하거나 단순히 수의계약이라고 쓰는 것으로는 예외를 확정하지 않는다.
  이 예외는 영리기업에 실제로 남아 있는 과도한 소기업 제한(v15)을 자동 면제하지 않는다.
- 제2조의2①1호 단서의 소기업 3인 이하/소기업 경쟁 유찰 사유는
  1억 미만 중소기업 칸의 v17을 면제한다. 일반적인 재공고라는 말만으로 적용하지 않는다.
- 제2조의2①3호의 제조 소기업 3인 이상·조합 공동사업이 명시되면
  중간 구간 소기업 칸의 v15를 면제한다. 공동수급/컨소시엄은 같은 뜻이 아니다.
- 고액 일반제품 + 공동사업을 함께 추출한 경우는 `unresolved_high_joint_scope`로 보류한다.
  국가 제21조①8의2·지방 제20조①11은 판로지원법 제7조의2 경쟁제품 특례에 연결되므로,
  이 사실만으로 고액 일반제품까지 면제하거나 위반이라고 단정하지 않는다.
  이 특수 조합의 독립 검토는 남아 있다. 일반표의 고액 두 빈칸과는 별도 문제다.

- `PPS-DEV-080`, D0의 4.입찰 참가자격 다목은 영리기업에 소기업·소상공인 확인서를

  일괄 0으로 내리면 그 소기업 제한을 놓친다. 사례 ID나 문장을 프롬프트에 넣지 않았다.

## 구현과 A2 공유 계약

[script.py](../../../script.py)의 `COMPANY_SIZE_PROMPT`, `company_size_schema`,
`verify_company_size`가 세로축·결정표를 소유한다. `BAND_ITEMS`는 v14~v18 다섯 개다.
N1(`SPLIT_ITEMS`)·N3(`PRODUCT_ITEMS`)는 꺼져 있다. 기존 v13 선택 재검증은 유지한다.

추가 호출은 공고당 한 번이며 기존 모델 인스턴스·배치·토큰 예산·재시도를 재사용한다.
합동 프롬프트 및 합동 디코딩 스키마는 기존 HEAD와 동일하다.
합동 프롬프트 SHA-256: `56f73f0bb2218516ba60e4fe09088eb19bb5279eaa00d2a47a1bd6f489d72c8e`.
금액 구간 판정은 코드가 하고, 모델에는 위반 여부를 묻지 않는다.

별도 JSON `company_size`의 공유 필드는 다음과 같다.

- `qualification`: `small_only`(소기업·소상공인), `sme_allowed`(중기업 포함 중소기업),
  `unrestricted`(기업 규모 제한 없음), `unknown`(미확인). unknown은 네 번째 기업등급이 아니다.
- `qualification_quote`, `qualification_complete`: 실제 참가자격 원문 인용과 관측 상태.
- `scope`, `scope_quote`: 일반/경쟁제품/별도 범위/미확인 및 구매대상 인용.
- `priority_exception`·`size_exception` 및 각각의 인용: 위 예외들을 분리한다.

**A2는 이 `qualification`과 인용을 재사용하면 된다.** A1은 v13을 수정하지 않으므로
현재 v13 호출을 합치거나 대체하는 것은 A2 통합 시 할 일이다. 원응답은
`phase=company_size`, 판정 사유는 `company_size_verified`, 실제 문서 예산은
`company_size_input` 이벤트에 남긴다. 기본 제출 실행에서는 원응답 본문을 기록하지 않는다.

실패/필드 결손/원문에 없는 인용/미확인 범위는 기본 판정을 보존한다. 부재 새 판정은
완전관측·무탈락·문서 미절단·자격구간 관측을 모두 요구한다. 이 보수적 한계 때문에
dev v16 양성 1건·v18 양성 2건은 문서 절단으로 새 부재 판정이 보류될 수 있다.
문서를 늘리거나 별도 호출을 추가하지 않았다. 기존 기본 판정 자체를 0으로 지우지는 않는다.

`company_size_baseline_submission.csv`는 v13 검증까지 적용하고 A1만 적용하지 않은
같은 회차 비교 기준이다. `baseline_submission.csv`(합동 첫 판정)와 구분한다.
[replay_run.py](../../../tools/replay_run.py)는 새 원응답과 건별 문서 예산도 재생한다.

## 로컬 검증과 실행 한계

### Colab 게시 전 확인

사용자 요청으로 `LittleBitAI/a1-company-size-v14`에 A1 후보를 커밋·게시한다.
main 병합·회차 A의 A2 전체 통합·대회 제출은 이 게시에 포함하지 않는다.
노트북은 해당 커밋 사본을 새로 열고 `REPO_REF`만 같은 SHA로 바꾸는 clone 경로를 사용한다.
진단 기본값과 추론 설정은 유지한다. 무라벨 6,000건은 별도 실행이다.

패키징 재검사에서 submit SHA `cc904a30…`가 이전 준비본과 같았다.
전체 discover에서 오래된 `reports/team-d/final/hashes.json`의 script 해시 불일치를 발견해
기존 `tools/record_team_d_hashes.py`로 갱신하고 해당 검사를 통과했다.
`tests/test_setup_agents.py`는 별도 `--wiki` 입력이 필요한 검사다. discover 기본 호출에서는
입력 부재로 실패했고, 허브 경로를 명시한 재검사에서도 위키 설치/훅 검사 실패 3·오류 1이 남았다.
이 별도 설치 검사는 통과로 기록하지 않으며 A1 추론·Colab 실행 검사와 구분한다.
해당 위키 설치 검사 외 180개 검사는 별도 실행에서 모두 통과했다(39.677초).
