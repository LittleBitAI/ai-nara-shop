# C-variance 집계 절차 — 회차 전에 고정한다

담당 C · 2026-09-26 · **이 문서는 결과를 보기 전에 쓰였다. 결과를 보고 고치지 않는다.**

## 0. 경로 규약

| 쓰는 말 | 무엇 |
| --- | --- |
| `<inbox>` | 받은 결과 ZIP 을 푼 곳 |
| `<run>` | 등록 뒤 `reports/runs/<run-id>/` |
| `<tmp>` | 아무 빈 작업 폴더 |

## 1. 등록

```bash
py -X utf8 tools/register_run.py --inbox <inbox> --code-commit 772ca1284c8918c1fa4ca5729cc15dfe4dedb2d4
```

> 2026-09-27 덧. 2차 시도는 전용 노트북(`run/c-variance-n6` @ `1928c35`)으로 돈다.
> 그 브랜치의 `script.py` 는 `772ca12` 와 바이트가 같고 노트북의 `REPO_REF` 도
> `772ca12` 라, 회차가 적는 `source.json` 의 `commit` 은 `772ca12` 다.
> **`--code-commit` 은 위 그대로 `772ca12…` 를 쓴다.** 절차는 안 바뀐다.

등록 규약은 `docs/runs.md` 가 소유한다. 이 회차는 `submit.zip` 이 없는 진단 회차이므로
그 문서의 "부분 GPU/혼합 재생 등록" 항목을 따른다 — `register_run.py` 가 한 쌍을 요구하면
보관 규약대로 손으로 등록하고 그 사실을 적는다.

## 2. 바이트 재현 — 여섯 통과 각각

```bash
git show 772ca12:script.py > <tmp>/pin.py

for k in 01 02 03 04 05 06; do
  py -X utf8 tools/replay_run.py --case <run>/var-$k --script <tmp>/pin.py \
    --output-dir <tmp>/verify-$k --verify || echo "재현 실패 var-$k"
done
```

`--verify` 가 통과해야 그 통과의 CSV 를 근거로 쓴다. 하나라도 실패하면 그 통과를 빼고
몇 회로 집계했는지 적는다.

## 3. 집계

```bash
py -X utf8 reports/team-c/c-variance/aggregate.py \
  --runs <run>/var-01 <run>/var-02 <run>/var-03 <run>/var-04 <run>/var-05 <run>/var-06 \
  --output reports/team-c/c-variance/variance.json
```

이 스크립트가 내는 것은 넷이고 **그 넷만 보고에 쓴다.**

| | 무엇 | 왜 |
| --- | --- | --- |
| 0 | 설정 대조 (`code`/`input`/`records` 해시 · `seed` · `temperature` · 예산 · `debug_responses`) | **먼저 본다.** 갈리면 나머지 수를 변동폭이라 부를 수 없다 |
| 1 | 통과별 Macro 와 **최소 · 최대 · 범위** | 판정 문장이 쓰는 수 |
| 2 | 쌍 15개의 **갈린 셀 수**와 Macro 차이 | `reproducibility.md` 의 17~45셀과 견줄 값 |
| 3 | 항목별로 **몇 쌍에서 갈렸나**와 그 항목 F1 의 폭 | 어느 항목이 불안정한지 |

집계기가 `tools/score.py` 와 같은 Macro 를 내는 것을 기존 두 통과로 확인했다 —
0.774169492000 · 0.739802701384 로 자릿수까지 같다.

**표준편차를 쓰지 않는다.** 6회로 낸 표준편차는 신뢰구간이 넓어 "분포를 추정했다"는
착각을 준다. 쓰게 되면 N 을 반드시 함께 적는다(`README.md` §3-3).

## 5. 판정 문장 틀 — 결과를 보고 구조를 바꾸지 않는다

빈칸에 수를 넣는다. 문장의 구조는 지금 정해졌다.

> 같은 코드 `772ca12` · 같은 입력 · 같은 설정으로 dev 200건을 **N회** 돌렸다.
> 관측 N회의 Macro 범위는 **X** 다(최소 `___` · 최대 `___`).
> 쌍 15개의 갈린 셀은 **`___`~`___`** 개다.
> **따라서 X 보다 작은 Macro 차이는 한 쌍의 회차로 판정하지 않는다.**
> 이것은 관측 N회의 범위이며 분포가 아니다. 더 큰 흔들림이 없다는 뜻이 아니다.

덧붙일 두 문장.

> 이 범위는 **서로 다른 모델 실행** 사이의 것이다. 같은 원응답을 두 코드로 재생한
> 비교에는 쓰지 않는다 — 그쪽은 모델 출력이 같아 결정적이다.
>
> 서버 변동폭이 아니다. 같은 코드를 서버에 두 번 올린 적이 없다.

## 6. `reproducibility.md` 갱신 초안

집계가 끝나면 그 문서에 아래를 더한다. **지금 쓰지 않는다** — 수가 나온 뒤에 쓴다.

```markdown
## 2026-09-26 — 한 코드를 N회 돌려 범위를 처음 쟀다

지금까지의 관측은 코드마다 한두 쌍이었다. `772ca12` 하나를 N회 돌려 쌍 15개를 얻었다.

| | 값 |
| --- | --- |
| 코드 · 입력 | `772ca12` · dev 200건 (해시 동일) |
| 설정 | 여섯 통과 전부 `--debug-responses` 켬 |
| Macro 범위 | `___` (최소 `___` · 최대 `___`) |
| 갈린 셀 | `___`~`___` |

기존 표의 17~45셀 · 0.000008~0.010088 과 나란히 읽는다. 셀 수와 Macro 영향이
따로 논다는 것은 그대로다 — 9/25 의 12셀 · 0.034367 이 그 극단이다.
```

셀 하한·Macro 상한을 고칠지는 이 수를 보고 정한다. 지금 정하지 않는다.

## 7. 이 회차가 답하지 않는 것

- **서버 변동폭.** 같은 코드를 두 번 올린 적이 없다.
- **왜 갈리나.** `temperature=0` 인데 갈리는 원인은 이 회차로 안 나온다.
- **다른 코드·다른 GPU 의 크기.** `772ca12` · A100 한 조합이다.
- **최악값.** 관측된 범위일 뿐이다.
- **재생 비교의 안정성.** 그쪽은 결정적이라 이 회차와 무관하다.
