**규칙을 적용하면 그 TP 5개가 정의상 전부 사라진다**(§4). 얻는 것은 측정하지 않았고,
잃는 것은 규칙의 구조에서 **바로 따라 나온다.**

### 카탈로그가 None 인 진짜 이유

`competitive_product(rec, codes)` 는 `codes` 가 비면 무조건 `None` 을 낸다.
그 `codes` 는 `direct_production_demand(rec)` 가 만드는데, 그 함수는
**참가자격의 직생 요구 문장**을 찾고 `DP_SANCTION` 이 걸리는 창은 건너뛴다.

```python
if DP_SANCTION.search(window):
    continue                    # 계약 후 제재 안내이지 참가자격이 아니다
```

dev 200건 중 직생 요구 문장을 찾은 것은 **40건뿐**이다. 나머지 160건은
**카탈로그 대조가 아예 실행되지 않는다.** 즉 `None` 은 품목에 대한 관측이 아니라
**직생 요구 문장을 못 찾았다는 사실**이다. 이것은 B-1 이 v10 15건 전부에서 본 것과
같은 막힘이다.

**없는 관측을 "아니다" 로 읽는 것이 이 후보의 오류다.**

## 4. 규칙이 무엇을 부수는가 — 구조에서 바로 나온다

후보 대상 30건의 현재 C 항목 성적은 **TP 5 · FP 7 · FN 16** 이다.
그 TP 5개가 어디에 있는지가 결정적이다.

| 공고 | 현재 셀 | 경쟁제품 정황 |
| --- | --- | --- |
| 061 | **v10:TP** · v11:FN | **라벨 v11=1** |
| 062 | **v10:TP** · v11:FN | **라벨 v11=1** |
| 064 | **v10:TP** · v11:FN · v20:FP | **라벨 v11=1** |
| 068 | **v10:TP** · v20:FP | — |
| 069 | v10:FN · **v13:TP** | **라벨 v13=1** |

두 게이트가 `competitive` 를 **직접** 요구한다.

```python
# script.py:723 — v10
"v10": (facts.get("scope") == "competitive" and quoted(facts.get("scope_quote")),
        "direct_production"),
```

```python
# script.py — company_size_products()
# 항목명이 그대로 조건이다 — v12는 "일반제품", v13은 "중기간 경쟁제품"이다.
# 앞은 general, 뒤는 competitive에서만 설 수 있다.
```

**`scope` 를 `general` 로 뒤집으면 v10 은 적용 대상에서 빠지고 v13 도 설 자리를 잃는다.**
따라서 위 5개 TP — v10 넷(061·062·064·068)과 v13 하나(069) — 는 **전부 사라진다.**
측정이 아니라 규칙의 정의에서 따라 나온다.

항목당 양성이 5~8건이므로 **한 건이 F1 을 0.1 넘게 움직인다.** TP 5개는 작은 수가 아니다.

### 그리고 대상 밖으로 번진다

`_company_size_bands` 는 `scope in ("competitive", "other")` 이면 `outside_general_scope`
로 **v14~v18 밴드를 통째로 닫는다.** `general` 로 뒤집으면 그 30건에서 **밴드 다섯 항목이
새로 열린다.** A-2 가 인용한 H3 실측에서 `scope`+`scope_quote` 만 교체해도 **v18 밖 31셀**이
움직였다. 이 규칙의 번짐은 그보다 작다고 볼 근거가 없다.

## 5. 얻는 쪽은 얼마인가 — 재지 않았다

FN 16건이 후보 대상 안에 있다. 그중 일부는 `general` 로 뒤집혀야 열리는 자리일 수 있다
(039·040·044·041 의 v18:FN 이 A-2 가 본 그 자리다). **그러나 재지 않았다.**
CPU 재생이 승인 전이고, 전제가 이미 틀렸기 때문이다.

**얻는 쪽을 모르는 채로 잃는 쪽만 확정된 상태다.** 그 상태에서 규칙을 만들지 않는다.

## 6. 증거 수준

**CPU 사실 조회 + 라벨·원문 대조 + 코드 읽기.** 모델 호출 **0회** · GPU **0초** ·
추가 추론 시간 **0초** · 제출 CSV 미생성 · 후보 없음이라 **TP/FP/FN 전→후도 없다.**
저장된 `company_size` 원응답을 다시 파싱했을 뿐이다(**저장 응답 재사용**).
실제 GPU 회차·대회 서버와 무관하다.

## 8. 미확인 사항

- **얻는 쪽의 크기.** FN 16건 중 몇이 열리는지 재지 않았다(§5).
- **밴드 번짐의 실제 셀 수.** `outside_general_scope` 가 열리며 v14~v18 에 몇 셀이
  생기는지 재지 않았다. H3 의 31셀은 다른 변경의 수치다.
- **라벨이 옳은지.** 7건이 경쟁제품이라는 것은 **라벨과 고시 품명 대조**이지 조문 판단이
  아니다. 라벨이 틀렸을 가능성은 이 보고서가 다루지 않는다.
- **품명 문자열 대조의 신뢰도.** 고시 616 품명 중 4자 이상만 공백 제거 후 포함 검사했다.
  `기타행사기획및대행서비스` 같은 일반적 서비스명은 **우연히 걸릴 수 있다.**
  그래서 §3 에서 라벨(7건)과 품명(11건)을 **따로** 셌다.
- **무라벨 20,000건에서의 분포.** `train_unlabeled.jsonl` 이 저장소에 없어 못 잰다.
