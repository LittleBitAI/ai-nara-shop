## 3. `fit_to_budget` 은 문서를 자르지 않는다

지시가 `fit_to_budget` 의 조립 순서 diff 를 요구했다. **그 함수에는 조립 순서가 없다.**

```python
def fit_to_budget(rec, system_prompt, runner, max_chars, budget=PROMPT_BUDGET, products=()):
    while True:
        msgs = build_messages(rec, system_prompt, max_chars, products)
        n = runner.count_tokens(msgs)
        if n <= budget:
            return msgs, n, max_chars
        ...
        max_chars = max(128, int(max_chars * min(0.85, budget / n * 0.95)))
```

`fit_to_budget` 은 `max_chars` 를 줄이며 **재시도**할 뿐이다.
실제 조립·절단은 `build_context`(`script.py:255`)가 한다 — `DOC_ORDER` 로 정렬한 뒤
앞에서부터 채우고, 예산이 모자라면 그 문서를 `body[:available]` 로 자른다.

```python
DOC_ORDER = ["공고문", "규격서", "과업지시서", "제안요청서", "예외공표서", "기타"]
```

**공고문이 이미 맨 앞이다.** 참가자격 절은 대개 공고문에 있으므로,
"참가자격 절을 앞에 배치" 라는 변경이 문서 단위에서는 **이미 되어 있는 상태**다.
