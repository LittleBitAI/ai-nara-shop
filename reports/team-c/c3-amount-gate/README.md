### 8-1. 두 회차에서 같은 게이트를 돌린 결과

PR #31 이 낸 `colab-1789695980726180378` 은 같은 모델·같은 공고인데 **판정을 묻는 방식만**
다르다(별도 `판정` 칸 제거 + 보수화 지시 두 문장). 양성 총수가 370/600 → 66/600 이다.
같은 금액 게이트(조문값)를 두 회차에 똑같이 씌운 결과다.

| 항목 | 느슨 `…172468461` 전 → 후 | 보수 `…726180378` 전 → 후 |
| --- | --- | --- |
| v16 | 6/139/0 · 0.079 → **6/39/0 · 0.235** | 1/29/5 · 0.056 → **1/17/5 · 0.083** |
| v18 | 4/109/3 · 0.067 → **4/51/3 · 0.129** | 2/34/5 · 0.093 → **2/29/5 · 0.105** |
| v20 (게이트 없음) | 3/109/2 · 0.051 | 0/0/5 · 0.000 |

**읽는 법.**

1. **게이트의 방향은 두 회차에 다 선다.** v16·v18 모두 F1 이 오르고 **TP 를 하나도 안 지운다.**
   금액 게이트는 후처리라 판정을 묻는 방식과 직교한다 — 이것이 회차를 가로질러 서는 주장이다.
2. **절대 수치는 회차의 것이다.** "FP 139→39" 는 느슨한 회차의 값이고 보수 회차에서는
   "FP 29→17" 이다. 어느 쪽도 다른 쪽의 예측값이 아니다.
3. **어느 회차도 쓸 만하지 않다.** 느슨은 정밀도가, 보수는 재현율이 무너진다.
   v16 은 지지 6건에 TP 가 6 아니면 1 이고, v20 은 보수 회차에서 양성 판정이 아예 0 이다.
4. **2.2억과 2.3억이 보수 회차에서는 같은 값을 낸다**(둘 다 1/17/5). 경계 구간에 걸리는
   오탐이 그 회차에는 없다. 조문값을 쓰는 근거는 수치가 아니라 조문이므로 결론은 그대로다.

**출처와 재현.** PR #31 이 머지돼(`ca9dbe7`) 보수 회차가 `reports/runs/` 에 들어왔다.
`replay_amount_gate.py` 를 그대로 돌리면 **두 회차가 같이 나오고** `gate-result.json` 이
둘을 다 담는다. 없는 회차는 건너뛰며 그 사실을 출력하는 동작은 그대로 둔다 — 회차 보관본을
아직 안 받은 작업 폴더에서도 스크립트가 죽지 않게 하기 위해서다.

### 8-2. 대상 밖 19항목 회귀 — `compare_runs` 로 확인했다

PR #35 리뷰가 미이행으로 지적한 수용 기준이다. `replay_run` 으로 대체하고 넘겼던 자리를
실제로 `compare_runs` 를 돌려 닫는다. 기록은 `regression/compare/`.

```bash
py -X utf8 tools/replay_run.py --case reports/runs/colab-1789655036303880754/dev-debug --verify
py -X utf8 tools/replay_run.py --case reports/runs/colab-1789655036303880754/dev-debug \
  --candidate experiments/sme_candidate.py --output-dir reports/team-c/c3-amount-gate/regression/replay
py -X utf8 tools/compare_runs.py \
  --before reports/runs/colab-1789655036303880754/dev-debug/submission.csv \
  --after  reports/team-c/c3-amount-gate/regression/replay/submission.csv \
  --truth  open/dev_labels.csv --items v16,v18 \
  --output-dir reports/team-c/c3-amount-gate/regression/compare
```

도구가 낸 문장을 그대로 옮긴다. 손으로 세지 않았다.

```text
Macro F1  0.218203523963 → 0.218203523963  (+0.000000000000)
바뀐 셀   0 / 4800   (대상 밖 0)
```

**대상 밖 변화 0 셀이다.** 후보가 v16·v18 외의 어떤 셀도 건드리지 않는다.

**이것이 증명하지 않는 것.** 이 회차의 제출 파이프라인은 v16·v18 을 전부 0 으로 내므로
(`v16 0→0/0→0/6→6`, `v18 0→0/0→0/7→7`) **게이트가 거를 양성이 애초에 없었다.**
그래서 이 대조는 "게이트가 도움이 된다"를 증명하지 않고 **"대상 밖을 건드리지 않는다"만**
증명한다. 게이트의 효과는 8-1 절의 진단 회차에서만 보인다.
재생 CSV 는 회차 CSV 와 SHA-256 이 같아(`d1c4d8d9…`) 저장소에 중복해 넣지 않았다 —
위 명령으로 0.6초에 다시 만든다.

## 10. 미확인 사항

- 회차 ① 이 실제로 재현율을 살리는지는 **GPU 회차 없이는 모른다.** 항목 수 24→3 과
  출력 4칸이 진짜 원인일 수 있고, 그 경우 회차 ① 은 아무 효과가 없다.
- 금액 게이트는 **별도 진단 질의의 판정** 위에서만 쟀다. 제출 파이프라인의 판정 위에서는
  한 번도 재지 않았다. 두 진단 회차의 값이 서로 4배 가까이 다르므로(8-1)
  **회차 ① 이 내는 판정에서 FP 39/51 이 그대로 나온다는 보장은 없다.**
  회차를 가로질러 서는 주장은 "F1 이 오르고 TP 를 안 지운다"는 방향뿐이다.
- 판정을 묻는 방식의 어느 변수가 무엇을 만드는지 아직 갈리지 않았다. PR #31 이 움직인 것도
  **칸 제거와 보수화 지시 둘**이고, 앞선 세 변수(항목 수 24→3, 근거 null 해제, 출력 형식)와
  합쳐 최소 다섯이다. 회차 ① 은 그중 하나만 푼다.
- v20 라벨이 무엇을 재는지 확정하지 못했다. 보수 회차에서는 v20 양성 판정이 **0건**이라
  그 회차로는 게이트를 평가할 수조차 없다.
- 서버 제출·리더보드 영향은 전혀 측정하지 않았다.
