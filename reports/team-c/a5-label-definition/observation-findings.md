# A5 후속 원문 감사 — 발화 1.033배는 scope 타당성을 보장하지 않는다

후속 [브리프 3 대조](catalog-findings.md): 메타 적중 15/34·특이사항 5건을 재현하고
추가 네 건의 실제 규격을 감사했다. 충전기 외 확정된 새 반례는 없으며 조건별 미확정을 기록했다.

2026-09-21. 새 모델 호출 없음. [감사 코드](observation_audit.py)와
[83건별 근거·전체 입력 분포](observation-audit.json)를 생성했다.
회차 2의 83건(dev 술어 9 + 무라벨 술어 74)에 대해 원문 위치·검증 탈락·카탈로그 언급을
전부 대조했다. **83건의 v11 정답 라벨을 새로 확정했다는 뜻이 아니다.** 미확정도 결과에 남겼다.

## 결정

현재 H2의 남은 18회차 연속 수집은 종료한다. H2는 **채택 보류**다.
단순 인용 일치가 경쟁제품 지정의 특이사항 충족을 보장하지 않는 반례를 실제 발화에서 확인했다.
카탈로그 코드 존재만 요구하거나 절단·인용 보호를 완화하는 수리는 채택하지 않는다.
운영 코드·후보·프롬프트·스키마는 바꾸지 않았다.

## 발화한 충전기: 입력은 충분했지만 scope가 틀렸다

`PPS-D-002151`은 모든 H2 검증을 통과했다.

| 근거 | 값 |
| --- | --- |
| 모델 scope | competitive |
| 원문 D0 문자 [340,353) | `240kW 급속충전기2기` |
| 등록 및 본문 코드 | 2611170403 |
| 제공 CSV 세부품명 | 전기자동차용충전장치 |
| 제공 CSV 특이사항 | **50kW 이하에 한함** |

규격서에도 정격 출력 240kW(120kW*2)가 적혀 있다. 제공 고시의 용량 조건과 충돌한다.
저장된 실제 `max_chars`와 고정 코드로 입력 메시지를 재구성했고,
**50kW 특이사항과 240kW 구매 문구가 둘 다 모델 입력에 있었음**을 확인했다.
모델 프롬프트에도 특이사항을 충족해야 competitive라고 이미 지시돼 있다.
자료를 더 넣거나 같은 H2로 더 많은 공고를 수집하는 것만으로 이 검증 공백이 해결되지는 않는다.

이는 제공 자료에 의해 scope 관측이 반박된 사례다. 비공개 정답을 얻은 것이 아니므로
무라벨 v11 FP=1이라는 정답 통계나 전체 정밀도로 바꾸지 않는다.

## 탈락한 펌프: 보호 검사를 풀면 잘못된 관측을 더 소비한다

`PPS-D-000860`의 모델 scope도 competitive다. 하지만 D0 [406,435)에
`중소기업자간 경쟁제품(완제품) 구매 사업이 아닙니다.`라고 적혀 있다.
본문 과업은 펌프 완제품 구매가 아니라 주요 부품 제작과 분해·설치·정비다.
현재 H2는 문서 절단 때문에 이 행을 제외했다. 이 사례의 scope 오류를 찾아서 제외한 것은 아니다.
따라서 탈락률을 낮추려고 절단 검사를 없애면 불완전 관측과 범위 오류를 함께 받아들일 수 있다.

| 나머지 무라벨 발화 | 30 | 원문·카탈로그 후보는 정리했으나 최종 scope/예외 타당성 미확정 |

34개 발화(dev 포함) 중 본문에 카탈로그 코드/이름이 문자 그대로 있는 것은 5건,
메타 코드에만 있는 것은 12건, 문자 일치가 없는 것은 17건이다.
**문자 불일치 17건을 음성으로 처리하지 않는다.** dev의 행사대행 TP 두 건도 여기에 속한다.
반대로 문자 일치가 있는 충전기도 특이사항에서 탈락한다. 일치 유무만으로 나눌 수 없다.

기업규모 관련 문자열·예외·직생 요구의 원문 창을 83건 모두 수집하고 문자 좌표를 검증했다.
발화한 34건 중 기업규모 문자열 검색에 걸린 `002161`은 판로지원법 제목과 직접생산확인
요구다. 기업등급 제한의 증거로 바꾸지 않았다. 그 밖의 일반 유찰 안내·부가세 면제 안내도
실제 우선조달 예외라고 읽지 않았다. **키워드 검색에 없다는 사실만으로 부재를 확정하지 않았다.**
탈락한 서류에도 신인도 가점·지원 안내·체크리스트가 있어, 기업규모 단어의 존재와
참가자격 제한은 여전히 분리해야 한다.

## 단순한 두 수리도 실제로 확인했다

- 기존 `competitive_product(rec, {'2611170403'})`는 충전기에 **True**를 반환한다.
  이 함수가 검사하는 특이사항은 추정가격 상한이며 50kW 사양을 해석하지 않기 때문이다.
  H2에 기존 코드 조회를 붙이는 것만으로는 이 반례를 막지 못한다.
- 기존 직생 요구에서 얻은 코드로 그 함수의 True를 요구하면 dev 040·061·062가 모두
  **None**이다. FP 하나뿐 아니라 H2가 회복한 TP 둘도 지운다. 이 경로로 고치지 않았다.

다만 이것만으로 나머지 18,000건의 **모델 발화율**을 계산하거나 방향을 확정하지 않는다.
회차 2의 1.033배를 전체 모집단 전이율로 읽을 근거는 없다.

## 추가 GPU가 답해야 하는 질문과 실행 경계

새로 필요한 질문은 “같은 H2가 몇 번 더 발화하는가”가 아니라
**“기존 한 호출에서 지정 품목과 그 특이사항을 충족하는 관측을 구분할 수 있는가”**다.
현재의 opaque한 scope 범주와 사업명 인용으로는 검증기가 그 판단을 확인할 수 없다.
충전기·펌프와 dev 040은 이미 본 진단 사례이며, 새 코드의 독립 평가 표본으로 세지 않는다.

후속 GPU 실험의 최소 계약은 다음으로 정했다. 구현·실제 실행 완료 보고는 아니다.

- 한 가설: 같은 company_size 호출에서 품목 지정 근거·조건을 판단하는 관측을 바꾼다.
  v11 후처리 조건과 다른 항목의 판단을 동시에 바꿔 효과를 섞지 않는다. 별도 서버 호출은 추가하지 않는다.
- 첫 파일은 dev 200건이다. 새 사실로 기준/후보를 같은 원응답에서 재생해
  v11 TP/FP/FN뿐 아니라 공유 사실을 소비하는 다른 항목 변화까지 검사한다.
  프롬프트 변경 효과는 기존 프롬프트 대조와 같은 고정 코드의 별도 반복으로 추론 변동을 함께 잰다.
  서로 다른 프롬프트의 응답을 비교하면서 같은 원응답 재생이므로 churn이 없다고 말하지 않는다.
  충전기 한 건에 맞춘 숫자/ID 예외는 통과 근거가 아니다.
- 서버 시간 여유는 820초, 허용 추가 dev 추론은 92.193초다.
  다른 H4 단계 비용이 같다는 가정에서 company_size 단계의 계획 상한은
  `246.985 + 92.193 = 339.178초/200건`이다. 6,380초 위에 증가분을 환산해 얹는다.
  모델 적재를 제외하고 H4와 같은 단계 시간 계측으로 비교한다.
  실제 총 추론 비용을 다시 재기 전에는 서버 통과를 주장하지 않는다.
- 이후 무라벨 검증이 필요하면 앞 2,000건을 제외한 18,000건에서 표집 목록·seed·평가 방식을
  **실행 전에** 고정한다. 대표 비율 목적이면 확률 표본을, 조건별 실패 진단 목적이면
  조건별 표본을 사용하고 두 분모를 섞지 않는다. 표본 크기를 지금의 배율에 맞춰 고르지 않는다.

이번 감사의 실행 결과는 **기존 H2 연속 수집 종료·운영 채택 보류·검증 조건 완화 기각**이다.
추가 GPU는 실행하지 않았다. 이후 실험에서 확인할 입력/출력과 시간 경계까지 문서화했다.
