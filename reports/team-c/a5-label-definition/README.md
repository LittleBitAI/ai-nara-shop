### H1: `직접생산증명서` 표기 허용 — 기각

[후보](../../../experiments/a5_dp_certificate_candidate.py)는 요구어·품목 조회·소비 규칙은 유지하고
`확인` 없는 증명서도 읽었다. 공용 추출기의 세 호출자(제품 규칙, company_size 제품, 금액표)에
같이 적용했다. 표기 변형은 dev에서 발견한 것이며 법령에서 얻은 새 제한 조건이 아니다.

| 결과 | HEAD → H1 |
| --- | --- |

| v13 | 4/9/2 → 4/9/2 |

변화는 PPS-DEV-110의 v12 한 셀이다. `제조사 직접생산증명서 또는 제조사의 공급증명원/기술지원확약서를
계약시 반드시 제출`을 새로 읽자, company_size의 general 경로가 v12를 올렸다.
자격 요구인지, 낙찰 후 선택적 제출인지도 가르지 못하는 표기 확대다.

동일 원응답 대조라 이 차이는 회차 churn이 아니다.

최초 후보 어댑터가 재생기의 `submission` 모듈 대신 별도 모듈을 잡아 카탈로그를 잃는 오류를
발견·수정했다. 잘못된 초기 재생 12셀 차이는 실험 결과에서 제외하고 `artifacts/`로 옮겼다.
최종 후보 self-check가 재생기의 모듈 선택과 패치 복원을 검사한다.

## v13 — 품명 문자열 연결은 이미 있다

HEAD의 `company_size_products()`는 `direct_production_demand()`의 코드·품명 조회를 이미 쓴다.
077의 `기타행사기획 및 대행서비스`처럼 숫자 코드가 없는 문장도 이름으로 연결된다.
인수인계의 “연결한 적 없다”는 전제는 이 HEAD에서는 맞지 않는다.

양성 6건과 오탐 9건의 합집합 15건에서 `공동사업` 문구는 0건이며 저장 사실의
`size_exception`도 모두 none이다. `제7조의2`만 검색하면 056·069의 국가계약법 시행령상
예정가격 작성 생략이 걸린다. 판로지원법 공동사업 예외와 다른 조문이므로 이 문자열로
오탐을 내리는 규칙은 만들지 않았다. 공동사업이 실제 없다는 확정까지 확대하지 않는다.

남은 두 FN은 서로 다르다. 074는 `직접생산증명서`가 줄바꿈되어 H1으로도 추출되지 않는다.
076은 품목 코드가 이미 조회되지만 모델이 `sme_allowed`로 읽어 small_only 경로에 안 들어간다.
품명 조회를 추가하는 것만으로 둘을 동시에 해결할 수 없다.

제공 판로지원법 제7조의2①은 지정 물품·용역 특례, ②는 공동사업 특례를 따로 둔다.
②만 검사했다고 예외를 전부 검사한 것은 아니다. 현재 제공 자료에서 ①의 지정 범위를
개별 품목에 연결하는 근거는 이 회차에서 확정하지 못했다. 법적 허용 범위나 라벨 우선순위를
추측해 운영 코드를 바꾸지 않는다.
