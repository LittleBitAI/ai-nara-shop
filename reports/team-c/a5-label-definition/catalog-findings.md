# A5 브리프 3 대조 — 코드 적중과 조건 충족을 분리한다

2026-09-21. 브리프 3의 83건을 재계산하고, 조건이 붙은 발화 5건의 제공 원문을 읽었다.
[재현 코드](catalog_audit.py), [건수·조건·원문 좌표](catalog-audit.json).
모델 호출·새 정답 라벨·운영 코드 변경은 없다.

## 판단

**메타 품목 대조는 사용한다. 용도는 지정 후보와 확인할 조건을 찾는 것이다.**
15/34는 코드가 지정 목록에 있다는 증거이며, 15건 모두의 실제 구매가 지정 조건을
충족하거나 v11 위반이라는 증거는 아니다. 특이사항 5건도 오류 5건을 뜻하지 않는다.
원문에서 충전기 외 네 건을 확인한 결과, 새로 확정할 수 있는 scope 반례는 없었다.
그렇다고 네 건을 모두 적합으로 확정하지도 않는다. 아래의 서로 다른 미확정 사유를 남긴다.

`조항호내용`의 특정 값을 필수 조건으로 넣는 후보는 기각한다. 새로 구현할 필요가 없다.
메타 코드 일치를 필수로 하는 후보도 dev TP 061·062를 모두 잃으므로 기각한다.
기존 H2의 연속 수집 종료·채택 보류를 유지한다.

## 재계산과 정정

| 대조 항목 | 발화 34건 | 탈락 49건 |
| --- | ---: | ---: |
| 메타 품목 목록 있음 | 17 | 12 |
| 등록 코드가 제공 목록과 일치 | 15 | 10 |
| 일치 행에 특이사항 있음 | 5 | 4 |

브리프 §3의 공고 단위 건수는 전부 일치했다. 여러 품목이 있는 공고는 한 번만 센다.
기존 감사의 “본문 코드/이름 언급 5, 메타에만 언급 12, 언급 없음 17”은
본문 품명까지 포함한 다른 집계다. 이번 15/34와 모순되지 않는다.

- CSV는 **전체 616행, 10자리 코드가 있는 615행**, 특이사항 185행이다.
  코드가 빈 한 행은 국방규격 `기동,총포,통신,일반장비카바류`다.
  브리프의 615는 코드 조회 분모로 맞지만 전체 CSV 행 수로는 한 행 적다.
  185/615=30.0813%, 185/616=30.0325%로 각각 소수 첫째 자리 30.1%, 30.0%다.
- §1의 발화별 조항호내용 빈도와 전체 dev 4/200·앞 무라벨 6/2,000도 재현했다.
  지정 문구를 필수로 요구하면 발화는 **dev 1건(061), 무라벨 0건**이다.
  “최대 1건”은 상한으로 거짓은 아니지만 실제 남는 무라벨 수는 정확히 0이다.
  062 TP를 잃으며 dev 040만 골라 제거하는 근거로 쓰지 않는다.
- §7의 두 정정은 기존 [회차 2 판단](round2-decision.md)에 이미 반영된 내용이다.
  shard01 적재 447.872513초, 고정 유한집합의 발화비와 모집단 추정 불확실성을
  구분한다는 판단을 유지한다. 적재 시간 정정은 H2 발화비를 바꾸지 않는다.

## 조건이 붙은 다섯 건의 원문 판단

원문 좌표는 `catalog-audit.json`의 `cases[*].evidence`에 기록했다.
각 인용과 해당 고시 조건이 저장된 `max_chars`로 재구성한 모델 입력에 모두 있음을 검사했다.
실제 문서에 없는 규격은 모델 입력을 늘려도 생기지 않는다.

| 공고 | 원문에서 확인한 것 | 판단과 남은 경계 |
| --- | --- | --- |
| 002151 충전기 | `240kW 급속충전기2기`, 고시 `50kW 이하에 한함` | 기존 scope 반례 유지. 코드 일치로 구제할 수 없다. |
| 000732 서버 | D1 CPU `6458Q * 2`, `Clk: 3.1GHz-4.0GHz` | CPU 2개는 관측됐다. 4.0을 기본주파수로 취급해 탈락시키면 안 된다. 3.1이 기본·4.0이 부스트라는 해석이라면 3.2 이하 조건에 맞지만, 원문은 두 값의 역할을 명시하지 않는다. CPU 모델명의 외부 사양을 끌어와 확정하지 않았다. x86 여부도 단순 모델명 추론과 직접 관측을 구분해야 한다. 모순 확정 아님. |
| 002069 혼합 전산장비 | D1 서버 `6507P 3.5GHz(8-core) * 1EA 이상 제공`, `최대 2CPU 장착 가능`; 데스크탑 41대 | 고시에서 x86 CPU 1개는 주파수 제한이 없다. 최대 장착 가능 2개를 납품 CPU 2개로 읽거나 3.5만으로 기각할 수 없다. `1EA 이상`은 정확히 1개 납품 확정도 아니다. 별도 데스크톱 품목은 조건 없는 지정 코드와 본문 구매가 일치한다. 서버 한 품목의 미확정을 전체 혼합 구매의 비지정으로 확장하지 않는다. |
| 001333 식재료/햄류 | 메타는 햄류. D0는 식재료 구매이며 `별첨 입찰품목 및 사양서 참조`, 품목별 단가 계약 | 입력은 D0 한 문서뿐이다. 참조한 품목 사양서를 확인할 수 없어 실제 납품 품목이 고시의 햄 조건에 해당하는지 미확정이다. 메타의 `햄류`만으로 본문 구매 범위를 대신하지 않는다. |
| 002106 드론 | D1 배터리 포함 56kg, 배터리 14.7±0.3kg, 프로펠러 4개, 비행반경 2km | 조건은 제외 기종이 아니면서 **자체중량≤25kg 또는 운용상승고도≤150m**다. 56kg은 자체중량과 같은 정의라고 바로 둘 수 없다. 한 배터리를 빼는 해석에서도 41.0~41.6kg이지만 고도 조건이 남는다. 2km는 반경이며 고도가 아니다. 원문에 운용상승고도 수치가 없어 조건 전체를 거짓으로 확정할 수 없다. |

햄의 `input_completeness.완전관측=True`와 “사양서를 참조하지만 입력은 D0뿐”은
동시에 관측된다. 전자는 제공된 문서의 추출 상태이며, 후자까지 보증하는 값으로 쓰면 안 된다.
현재 H2의 완전관측 검사 통과와 품목 조건 판단에 필요한 자료의 충분성은 다르다.
이번 관측을 근거로 입력 플래그를 재작성하거나 모든 별첨 언급을 일괄 탈락시키지 않았다.

## 구현상 무엇이 이미 있고 무엇이 없는가

현재 `script.sme_product_lookup()`은 메타 코드·본문 코드·품명을 이미 찾아
특이사항과 함께 company_size 입력에 넣는다. 따라서 “메타 코드를 이제 추가한다”는
수리는 이 다섯 건에서 새 정보를 공급하지 않는다. 다섯 건 모두 조건과 위 규격 인용이
기존 입력에 들어 있었음을 재현했다. 이전 보고의 메타 언급도 이 사실과 양립한다.

부족한 것은 조건을 분해한 관측이다. 서버는 실제 CPU 개수/장착 한도와 기본/최대 주파수,
드론은 자체/배터리 포함/이륙 중량과 고도/반경을 구분해야 한다. 햄은 자료 자체가 부족하다.
조건을 관측하지 못한 경우를 위반 또는 비지정으로 자동 치환하지 않아야 한다.
혼합 구매는 품목별 관측과 공고 전체의 적용 판단도 분리해야 한다.

따라서 이번 자료는 기존에 정의한 “동일 company_size 호출의 지정 조건 관측” 실험에
**분기와 미확정 사례를 제공하는 진단 자료로 채택**한다. `조항호내용` 필터,
코드 일치 필터, 무조건 숫자 상한 필터는 채택하지 않는다. 이미 본 다섯 건은
차기 후보의 독립 평가 표본이나 무라벨 정밀도 분모로 세지 않는다.
새 GPU 실행 패키지는 이번 브리프 대조에서 만들지 않았으며 GPU 성능 개선도 주장하지 않는다.
기존 시간 경계(서버 여유 820초, 추가 dev 추론 92.193초)는 유지된다.
