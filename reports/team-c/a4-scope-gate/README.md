## 왜 한 묶음으로 쟀나

다섯은 "재현율은 있는데 적용범위 게이트가 없다"로 묶인 항목이다. 하나씩 넣고 이긴 것만
남기면 항목당 양성 5~8건 위에서 다섯 번 고르는 것이고, 그것이 dev 과적합의 경로다.
한 번에 넣고 한 번 쟀다. 각 규칙은 dev 문자열이 아니라 항목 정의·제출 계약·제공 조문에서 나온다.

## 기준선을 `dev`가 아니라 `dev-debug`로 잡은 이유

회차의 `score/metrics.json`은 `dev/submission.csv`를 채점한 것이고, 재생이 쓰는 원응답은
`dev-debug/`에 있다. 같은 코드의 서로 다른 추론 회차라 항목별 TP/FP/FN이 다르다
(예: v24가 dev 5/32/3, dev-debug 5/36/3). 이 보고의 전·후는 둘 다 `dev-debug` 안이다.
`dev`의 0.599316과 이 보고의 0.593846을 같은 저울로 읽지 않는다.

HEAD 재생이 회차 CSV와 바이트 동일함을 먼저 확인했다(`--verify`, 그리고 후보 없는 재생).

## 3. v23 — 현장설명회 (공고기간) (0.286 → 0.500)

이 항목만 내림과 올림을 같이 했다. 모델이 7건 중 1건만 맞히고, 조문이 날짜 산술 하나다.

적용범위. [items v23](../../../docs/items.md)이 "계약방법 협상 + 계약법 지방만 적용",
"국가계약법: 해당 없음(위반 성립 불가)"으로 못박았다. 범위 밖은 0이다. dev 200건 중 41건이 범위다.

조문. 「지방자치단체 입찰시 낙찰자 결정기준」 제7장 제3절 2-다:

> 제안요청서 설명은 제안서 제출마감일의 전일부터 기산하여 … 기간 전에 실시해야 한다.
> 이 경우 입찰공고는 제안요청서 설명일의 전일부터 기산하여 7일전에 공고해야 한다.

전일부터 기산해 7일이므로 적법한 최소 간격은 `설명일 − 공고게시일 ≥ 8`이다.
설명일을 못 찾으면 발화하지 않는다 — 설명을 안 하면 이 조항이 적용되지 않는다.
예규 제3절 2-나가 교부·설명 생략을 예정하므로, 생략을 적어 둔 공고는 제외한다.

### 안 재고 넘어간 것과, 재서 죽은 것

- `191`이 `139`·`140`과 같은 7일인데 정답이 0이다.

  **여기 적혀 있던 "세 건의 차이는 `191`만 긴급공고"라는 설명은 사실이 아니다.**
  `meta.긴급공고여부`를 다시 읽으면 `139` = `None`, `140` = `Y`, `191` = `Y` 다.
  긴급을 예외로 두면 정답이 1인 `140`도 함께 빠지므로, 그때 적어 둔 `FP 0 · F1 0.571`은
  성립하지 않는다. 뒤이어 적은 조문 근거(시행령 제35조④·예규 제3절 1-나의 완화는 제안서
  마감일 기준이고 설명일 기준 7일에 대한 완화 조항이 없다)는 그대로 유효하며, 안 넣은
  결론도 그대로다 — 다만 그 근거는 "유추"가 아니라 **수치로도 성립하지 않는다**는 것이다.

  D11(PR #133)이 이 세 건을 다시 갈랐다. 정답 양성 다섯은 전부 「설명일 → 제안서
  제출마감일」 축에서만 위반이고, `191`을 배제할 조문 근거는 법령 패키지에서 찾지 못했다.
  자세한 것은 [d11-v23-axis-a](../../team-d/d11-v23-axis-a/README.md)가 소유한다.
- `141`·`27`은 설명일까지 20~21일로 충분하다. 위반이 설명일 이후 쪽에 있다는 뜻이다.
  같은 2-다 앞부분(설명은 마감일 전일부터 기산해 금액구간 기간 전에 실시)을 `141`에 대 보면
  32.7억이라 40일이 필요한데 설명 2/6에서 개찰 2/26까지 20일이라 위반이 맞다. 그런데 `27`은
  5,454만원이라 10일이면 되고 실제 16일이라 이 축으로도 안 잡힌다. 제안서 마감일이 meta에
  없어 개찰예정일자로 근사해야 하는 것도 걸린다. 넣지 않았다.
- 입찰공고 기간(제35조⑤, 마감일 기준 10·20·40일)으로 잰 판본: 지방+협상 41건에서

## 7. 이 보고가 증명하지 않는 것

- `script.py`를 안 고쳤다. 채택 전 후보이고 실제 회차·서버 제출에 들어간 적이 없다.
- 재생은 같은 모델 출력을 쓰므로 회차 churn이 없다. 그래서 여기 차이는 후처리의 효과다.
  그러나 프롬프트가 바뀌면 이 숫자는 다시 재야 한다.
- dev 200건의 수치다. 서버 1,853건에서 같은 비율이라는 근거는 없다 —
  같은 코드의 dev 0.599 대 서버 0.508이 그 간격이다.
- v9·v23은 0.6에 못 닿았다. v6만 목표선을 넘었다.
- §3의 "긴급공고 예외" 유추와 §2의 "규격서 한정"은 dev 수치만 있고 채택하지 않았다.
