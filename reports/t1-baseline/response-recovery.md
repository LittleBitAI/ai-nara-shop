## 실제 실행과 원인 경계

최초 제출 코드는 정상 24항목 응답 검증 실패 후 같은 형태의 단독 호출을 반복했다.
원인 메시지 없이 ValueError 종류만 노출하므로 동일 문구가 잘림·빈 응답·필드 오류·
호출 오류·응답 건수 오류에서 모두 발생한다. 최초 원인을 특정할 서버 응답은 없다.
사용자는 대회 서버 로그를 열 수 없다. 서버 로그 회수를 전제로 해결을 미루지 않는다.

`colab-results-1789613533157944500.zip`의 실제 57c78cf 실행에서는 별도 단계의
PPS-DEV-121/125/175가 2,048토큰에서 length 종료했고 JSON 파싱 실패 후 단일 항목
재시도로 복구됐다. 관측된 오류의 원인은 출력 잘림이며, 최초 서버 오류와 동일하다는 증거는 아니다.

최신 `colab-results-1789616952134769089.zip`은 e9e4022, script.py SHA-256
`631c7beb84c0d7a54b88d327c77bde938f048224d93003f67869da70595402e4` 실행이다.
샘플 10건/dev 200건의 두 단계 응답 420개 모두 첫 시도 stop/valid다.
dev 기본/최종 F1은 0.21663174707034358/0.2199212207545541로 과거 기준 미달이다.
errors=295는 FP+FN이며 실행 예외 수가 아니다. dev 추론 362.0+329.8초, 전체 911.049초.

## 수정과 검증

수정 전 실패 검사를 먼저 실행해 두 중단 경로를 재현했다.

- 기본 6항목 그룹이 잘못된 응답을 내면 해당 그룹만 단일 항목으로 더 나눈다.
  앞서 성공한 그룹은 재호출하지 않는다. 단일 항목 응답도 실패하면 원인을 유지해 종료한다.
  기본 단일 v10/v11/v13에 추가 단계용 facts 스키마가 섞이지 않도록 모드를 명시한다.
- 추가 3항목 호출·재시도가 실패하면 이미 정상 검증된 동일 공고의 기본 24항목을 보존한다.
  기본 응답이 없거나 형식이 잘못됐으면 보존 경로를 사용할 수 없다. 임의 0 채움은 없다.
- 기본 모델 정상 호출 건수는 전건이어야 한다. 추가 성공·검증·기본 보존 건수는 별도 집계한다.
  Colab은 추가 성공 + 보존 = 전체 건수를 확인하고 보존 건수를 표시한다.
  실패를 추가 모델 성공으로 집계하지 않는다. 점수 임계값은 유지했다.
- 영어 지시·한국어 법적 용어·평상시 프롬프트·판정 조건·정상 출력 경로는 유지했다.
  v13의 과도한 문자열 배제 조건은 별도 성능 과제로 남는다. 이번 변경은 정확도 개선 주장이 아니다.

## 아직 증명하지 않은 것

위 검사는 모델 없는 로컬 회귀 검사다. 새 코드의 GPU 분할 복구, 총시간, 품질 기준 통과,
대회 서버 성공을 대신하지 않는다. 서버 로그 없이도 같은 ZIP의 Colab 실행으로 새 코드를
검증할 수 있다. 진단 기록은 그 Colab 실행을 분석하는 용도이며 서버 통과의 근거가 아니다.
GPU/엔진 자체 고장, 기본 단일 항목 복구 실패, 시간 초과까지 무조건 성공하게 할 수는 없다.
기본 정상 응답 없는 성공 처리는 R4를 충족하지 않는다. 실제 서버 성공 전까지 T1은 진행 중이다.
