## 무엇을 바꿨나

운영 `script.py` 는 안 고쳤다. 후보는 운영 `postprocess()` 를 그대로 돌린 뒤 v24 가 0 인 공고에서만
`budget_mismatch()` 를 보고, 불일치를 찾으면 v24=1 · e24=본문 금액 구절로 올린다. 내리지 않는다.
e24 는 `clean_evidence()` 를 통과한 경우에만 쓴다(본문 부분문자열, D4-4).

금액은 라벨에 바로 붙은 금액 하나를 읽는다(`기초금액 : 금2,046,000원`). 라벨 뒤에 `이상·미만·이하·초과` 가

라벨은 금액 표기의 뜻으로 나눴다.

`+` 산식은 라운드 7 의 "`=` 뒤 총액" 의도를 `×` 만으로 구현한 파서 결함이고, 나머지는 하나씩 규칙이 더 필요하다.

## 판정 근거

작업서의 채택 기준은 "올린 셀의 정밀도가 v24 현재 F1 의 절반(0.167)보다 높아야 F1 이 오른다" 이다.

- dev: 올린 셀 1/1. 판정 불가(셋 이하).
- 무라벨 표본 두 번 40건: 불일치 꼴 17 · 모호 7 · 오탐 꼴 16. 불일치 꼴만 맞는다고 보면 상한 17/40 = 0.43 이다.
- 라벨이 불일치 꼴을 양성으로 보는 비율은 dev 에서 두 건뿐이다 — `029` 1 · `044` 0 (둘 다 두 필드가 등록과 다르다).
  그 1/2 를 곱하면 약 0.21 이다. 0.167 과 거의 같고, 곱한 비율의 근거가 두 건이다.
- 배율 0.69 는 채택된 v19 0.67 과 비슷하고 v6 1.11·v9 1.16 보다 낮다.
- 새 양성이 무라벨 원응답 2,000건에서 14(0.7%)다. 비공개 1,853건이 같은 비율이면 약 13건이고,
  정밀도 0.21 이면 TP 약 3 · FP 약 10 이다. 서버 분포는 재지 않았으므로 추정이다.

## 결론 — 채택

작업서가 미리 정한 판정 규칙을 그대로 적용한다. 정밀도 추정은 셋 다 문턱 0.167 위다 — dev 올린 셀 1/1,
dev 축 발화 1/2 = 0.50, 무라벨 꼴에 dev 비율을 곱한 가장 비관적인 값 0.21. 배율 0.69 는 채택된 v19 0.67 과 같은 범위이고
경고 범위(v8 0.28·v4 0.34)가 아니다. 그러므로 채택이다.

다음은 W5 4단계다 — 독립 리뷰 뒤 운영 `script.py` 로 옮기고, 다른 규칙과 묶지 않고 단독으로 제출한다.
