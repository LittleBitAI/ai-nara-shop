## 모델 지정 문장 — 코드보다 먼저 정한 표

H1 은 모델이 v9=1 을 낸 공고에서 `docs` 전부(문서 종류로 좁히지 않는다)를 줄 단위로 훑어
아래 "지정" 꼴의 줄을 찾는다. 표에 없는 꼴은 코드에 넣지 않는다.
출처는 착수서의 표(QnA S7-4·14, dev·무라벨 인용 예)이고, dev 정답을 보고 낱말을 고르지 않았다.

| 꼴 | 판정 | 코드의 조건 |
| --- | --- | --- |
| 머리말 `제조사`·`제조회사`·`모델`·`모델명`·`형식`·`형식명`·`품번` 뒤 `:` 와 값 | 지정 | 머리말 글자 사이 공백 허용(`모 델 :`). 값이 비었거나 기입란이면 제외. 한국어만 적은 값도 지정 |
| 브랜드 + 제품 식별자 | 지정 | 한 토큰에 라틴 문자와 숫자가 함께 있다(`GB10`, `IOD-750H`), 또는 라틴 낱말 뒤에 숫자 토큰이 온다(`ICP-OES 5900`, `RC PLUS 2`) |
| 기술·방식·칩 이름 | 지정 아님 | 라틴+숫자 식별자가 없으면 두 번째 꼴이 서지 않는다(`Maxwell 7칩`, `IRU … 광섬유 방식`) |
| 인증·등급·규격 표기 | 지정 아님 | 식별자가 `EAL\d`·`Tier-\d`·`IP\d\d` 이거나 바로 앞 10자 안에 `인증`·`등급`·`규격`·`표준`·`KS`·`ISO` 가 있으면 식별자로 세지 않는다(`CC인증 EAL4`, `eVGT 엔진(Tier-5)`) |
| 성능 하한 `… 이상` | 지정 아님 | 줄이 `이상` 으로 끝나면 제외. 기존 `V9_SPEC_FLOOR` 와 같은 조건 |
| 응찰자 기입란 | 지정 아님 | 값이 `_`·`.`·공백뿐이거나 `기재`·`작성`·`제안`·`별도`·`참조`·`해당없음`·`-` 만이면 제외. 머리말 앞에 `제안`·`입찰자`·`응찰` 이 붙으면 제외 |
| 기존 장비 설명·호환 요구 | 이 표로 정하지 않는다 | 따로 거르지 않는다. 식별자가 있으면 위 꼴대로 센다 — 착수서가 이 작업 밖이라 한 것이다 |

알려진 한계. 두 번째 꼴은 문맥(구매 대상인가)을 보지 않는다. 계측 장비·부품 모델명·`G2B` 도 식별자로 선다.
그래서 측정한 H1 은 문서 탐색에 머리말 꼴만 쓰고, 두 번째 꼴은 모델 인용을 볼 때만 쓴다 — 경위는 아래 "H1 은 기각한다".

### H1 은 기각한다 — 정규식으로 옮긴 표가 표대로 서지 않는다

발동 확인이 두 번 실패했고 그때마다 고쳐 다시 쟀다(W5 3). 기록으로 남긴다.

1. 식별자 꼴을 문서 탐색에 쓴 첫 판: dev v9 5/16/1. 익명화 토큰 `[지역:r1|…]` 의 `r1` 이 식별자로 섰다.
2. 익명화 토큰·주소를 지운 둘째 판: 5/15/1. `G2B`·공고번호 `C2026-1` 이 섰다.
   라벨 없이 dev 200건을 세면 식별자 꼴이 171건, 머리말 꼴이 17건에서 선다. 기저율 3% 항목에서 171/200 은 아무것도
   가르지 않는다. 그래서 문서 탐색은 머리말 꼴만 쓰고, 식별자 꼴은 모델 인용을 볼 때만 쓴다. 이 셋째 판이 위 표의 H1 이다.
   이 변경은 라벨 없는 발화 수에서 왔지만 dev 결과를 본 뒤에 했다는 점을 적어 둔다.
3. 셋째 판은 dev 에서 좋아 보이지만 무라벨에서 180건(2,000건 기준 62건)을 내리고 그중 지정 꼴이 상당수다. 인용 쪽 식별자 꼴이
   숫자로 시작하는 모델 번호(`12AYM-WST`)·`®` 가 낀 이름·콜론 없는 머리말(`모델 YANMAR`)·숫자 없는 브랜드(`NEXO GEO-T`)를
   못 알아본다. 바꾼 e9 도 둘이 응찰자 기입란이다(`◦ 제 조 사 : ◦ 모델명 :`, `1. 모델명 : 계약장비의 모델명 기록`).

더 고치면 무라벨 사례에 낱말을 맞추게 된다. "브랜드 + 제품을 구매 대상으로 적었나" 는 문맥 판단이고 정규식의 일이 아니다.
착수서가 예고한 `156` 의 비용(물품 내역표가 다시 지정이 됨)은 나타나지 않았다 — `펙사론` 은 머리말도 식별자도 아니라 내려갔다.

### 권고 — `V9_EQUIVALENT` 를 끈다(`off`), `V9_SPEC_FLOOR` 는 둔다

- 운영진 S7-14 는 동등 문구만으로 v9 를 정하지 말라고 했다. H2 는 창을 문장으로 좁혔을 뿐 여전히 그 문구 하나로 내리고,
  남은 12건 중 여덟이 "모델 + 동등이상" 꼴 — S7-14 가 그 문구만으로 정하지 말라고 한 바로 그 모양이다.
- HEAD 게이트가 무라벨 5,500건에서 내리는 41건 중 29건이 지정 꼴이다. 그대로 정탐이라면 `q` 는 0.7 안팎이고
  삭제형 채택 기준 `q < F/2`(v9 는 0.21) 를 크게 넘는다. 라벨링 전이라 측정값은 아니다.
  라벨로 확정하려면 41건 전수가 표본 전부다. A 의 D 감사가 쓴 Opus 5.5 라벨러의 v9 재현율은 dev 2/3 뿐이라 사람 확인이 낫다.
- 비용은 dev −0.003051(오탐 넷 복귀)이다. `088`·`090` 은 모델명이 아닌데 돌아오고, `110`·`160` 은 지정 꼴인데 정답이 0이다.
  앞의 둘을 맞는 이유로 내릴 규칙은 H1 에서 만들지 못했다.
- dev 를 덜 잃는 쪽을 원하면 H2(dev −0.001671)다. 대신 S7-14 와의 충돌이 남는다.
- 채택·제출은 A 가 정한다. 제출한다면 v9 변경만 단독으로 올린다.
