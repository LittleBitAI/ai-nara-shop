## 2. H1 을 코드로 옮기지 못한 이유

작업서는 H1 구현 전에 "정탐 4건이 전부 1단계에서 찾히는지 먼저 본다" 고 했다. 찾히지 않는다.

- `09` 의 문서에 있는 모델 비슷한 문자열은 `GB10 Grace Blackwell Superchip`·`Cortex-X925` 같은 칩 이름이다.
  표 4행은 칩 이름을 지정 아님으로 둔다. 표대로 옮기면 정탐을 내린다.
- 머리말 규칙(표 1행)만 기계로 옮기면 정탐 넷 중 `12` 하나만 찾는다. `052` 는 `모델명` 이 표 머리글에 있고
  값 `Agilent ICP-OES 5900` 은 몇 줄 뒤에 떨어져 있다. 반대로 `형식` 머리말은 `형식 : 보통형`·
  `형식: H.264/H.265` 같은 사양 분류에도 붙는다(`110`·`23`·`176`).
- 브랜드 + 식별자(표 2행)를 영문 낱말 뒤 숫자 섞인 토큰으로 옮기면 17공고 중 12공고 문서에서 걸린다 —
  `Intel Core i7-1185G7`(`088`), `ISO 9001`, `MIL-STD-810F`, `Intel Xeon Gold 6544Y`(`160`).
  부품·규격을 구매 대상과 못 가르므로 표 4행을 구현하지 못하고, 거의 모든 공고를 지켜 결과가 게이트 삭제와
  비슷해진다. 한국어 브랜드 `156`(`농협케미컬`)은 못 찾는다.

표의 칸(칩 대 제품, 규격 대 제품, 부품 대 구매 대상)은 의미 판단이다. 낱말을 더 붙이면 작업서가 금지한
"dev 인용에 맞춰 낱말을 고르는" 쪽으로 간다. 그래서 H1 의 뒷절반(문서에서 지정 문장을 찾아 없으면 내림)은
만들지 않았다. 앞절반 — `V9_EQUIVALENT` 를 뺀다 — 만 남는다.

## 4. 권고

`V9_EQUIVALENT` 를 뺀다. 이 PR 이 그 변경이다.

- 운영진이 그 표현만으로 v9 를 정하지 말라고 했고(S7-14), 게이트는 무라벨에서 지정 꼴 넷을 지운다.
  평가셋에 "모델명 + 동등 이상" 으로 적힌 정답 1 공고가 있으면 지금은 전부 0 이 된다.
- dev 비용은 −0.003051(오탐 +4)이다. 그 이득은 무라벨 배율 0.30 짜리라 활성 계획 규칙상 이득으로 세지
  않았던 값이다.
- H2 는 dev 비용이 절반이지만 S7-14 가 부정한 판정 방식(문구로 정함)을 좁혀서 유지하고, 무라벨에서 머리말
  지정을 하나 지운다.
- `V9_SPEC_FLOOR` 는 둔다. 한 PR 에 한 변경이고, 작업서가 그것을 정의 쪽 규칙으로 분류했다. 다만 깨끗하지는
  않다. dev 에서는 0셀이지만 무라벨에서 3셀을 내리고, 그중 둘은 제품·모델을 적은 인용이다 —
  `추천모델: TS-M1000EDM 동종, 동급 이상`(`PPS-D-000884`), `레이 4인승 EV(전기차) 이상`(`PPS-D-000607`).
  셋째는 `Core i5-3550s processor 또는 그 이상`(`PPS-D-014926`)이다. 인용이 `이상` 으로 끝난다는 것만으로
  내리므로 S7-14 와 같은 질문이 남는다. 다음 한 칸으로 A 에게 넘긴다.

올린다면 단독으로 올린다(작업서 §채택). #108(v3·v5·v6 묶음)·#109(v24 후보)와 같은 날 올리지 않는다.
