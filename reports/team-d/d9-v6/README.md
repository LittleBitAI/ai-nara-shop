# D9 — `단위=기초` 토큰으로 v6 을 판정한다

작업서: [docs/tasks/d-v6-basic-region.md](../../../docs/tasks/d-v6-basic-region.md) ·
조건표와 표본: [l2-conditions.md](l2-conditions.md) · 재생 산출물: [replay/](replay/)

규칙 넷을 **따로 켜고 따로 쟀다.** 어느 것을 채택할지는 A가 정한다. 여기서는 표와 권고만 낸다.

| 규칙 | 하는 일 | 켜는 법 |
| --- | --- | --- |
| U | 올림. 모델이 0인데 참가자격의 지역 제한 문장에 **토큰으로 확인된** 기초 신호가 있다 | `D9_V6_RULES=U` |
| L1 | 내림. 모델이 1인데 어느 지역 제한 문장에도 기초 신호가 없다(v6 정의 밖) | `D9_V6_RULES=L1` |
| L2-보수 | 내림. 지방 소액수의 견적의 관할 제한 예외 — (a)(b)(c) 를 전부 확인했을 때만 | `D9_V6_RULES=L2C` |
| L2-추정 | 내림. 같은 예외 — (a)(b) 만 확인하고 (c) 는 관할로 추정 | `D9_V6_RULES=L2E` |

기본값은 **아무것도 켜지 않음**이다. 켜지 않으면 이 절은 v6 을 건드리지 않고, 앞서 있던
v8·v7·v4·v3 재생이 그대로 재현된다. `D9_V6_ONLY=1` 은 그 넷을 꺼서 v6 규칙 하나의 변경 셀만 센다.

정의에 맞는 문장만 잡았다**(아래).

### U 가 올린 무라벨 7건 — 전수

7건 모두 참가자격의 기초 지역제한 문장이고, e6 **7/7 이 원문 부분문자열**이다.
5건이 국가계약 소액수의견적인데, 소액수의 예외는 지방 집행기준이라 U 의 제외 조건(지방+소액수의)에
걸리지 않는다. `002086` · `008965` · `012544` · `016619` · `017513` · `003977` · `012971`.

정탐을 내린 셀은 46건 중 하나도 찾지 못했다. 다만 이것은 **없다는 증명이 아니다** — 무라벨에는
정답이 없고, 그런 셀은 정의상 기초 신호가 안 보이는 셀이라 같은 방법으로는 찾을 수 없다.

## L2 표본 검토 — 최종 대상 25건 중 20건

`random.seed(20260923)`. 표와 근거 문장은 [l2-conditions.md](l2-conditions.md) 에 있다.

| 판정 | 건수 |
| --- | ---: |
| 예외 성립 — 제한 지역이 같은 문서의 납품·현장·과업 장소와 같은 `rN` | **7** |
| 판단 불가 | **13** |
| 불성립 | 0 |

판단 불가 13건은 장소 문장이 아예 없거나(`004096`·`006776`·`013882`·`015135`·`017027`·`021847`),
장소가 토큰 없이 서술되거나(`납품장소 : 수요기관 지정장소`, `사업위치 : [수요기관(지방정부)] 관내`),
장소 토큰이 제한 토큰과 다르다. **익명화가 지명을 지우기 때문에 사람이 읽어도 갈리지 않는다.**

**20건 전부 실제 기초 지역제한 참가자격 문장이었다.** L2 가 엉뚱한 셀을 집은 것은 없고,
갈리는 것은 "예외가 성립하느냐" 하나다. 그래서 두 판본의 차이는 그대로
**"모르는 17건을 예외로 볼 것인가"** 다 — L2-추정은 25건을 내리고 L2-보수는 8건만 내린다.

한 건은 규칙의 (c) 가 서는지 다툴 수 있다. `PPS-D-001958` 은 용역위치 줄에 제한 토큰 `r1` 과
다른 기초 토큰 `r2` 가 함께 있다(`용역위치: [수요기관(기초자치단체)] [지역:r2…] [상세주소]([기관(기초자치단체)|지역=r1] 본관동)`).
규칙은 `r1` 이 같으므로 관할로 본다.

## 권고 — U → L1 → L2 순

작업서의 권고 순서(L2 → U → L1)와 **다르다.** 그 순서는 무라벨 사전 필터 65건을 근거로
"이 작업의 무게는 L2 에 있다"고 본 것인데, 규칙을 다 적용한 재생에서 L2-추정은 25건,
L2-보수는 8건이었다. 사전 필터 수가 실제 변경 셀 수보다 컸다.

1. **U — 채택 권고.** dev 에서 +0.010101010101 이고 오탐 0, 대상 밖 셀 0 이다. 올린 두 건
   모두 정답 1 이고, 무라벨 7건도 전수 확인에서 정의와 맞았다. 배율 0.35 를 감수한다면
   이것이 가장 근거가 두터운 규칙이다.
2. **L1 — 채택 가능, 다만 dev 증거가 없다.** 무라벨 46건 중 39건이 광역 이름뿐인 제한이라
   정의상 맞는 내림이다. 하지만 dev 에서 0셀이라 **이 규칙의 이득은 한 번도 채점된 적이 없다.**
   U 와 묶어 올리면 서버에서 무엇이 움직였는지 못 가른다.
3. **L2 — 보류 권고.** 두 판본 다 dev 0셀이고 배율이 정의되지 않는다. 표본 20건에서 예외
   성립이 7건뿐이고 13건이 판단 불가여서, L2-추정은 **모르는 것을 예외로 보는 쪽**에 건다.
   제출한다면 L2-보수부터고, 그것도 U 가 서버에서 검증된 뒤다.

제출한다면 **v6 변경만 단독으로** 올린다(9/21 교훈). U 와 L1 을 묶으면 dev 이득은 같고
(둘 다 0.628528238474) 서버에서 갈리지 않는다.

## 구현하면서 드러난 것 — B에게 넘기는 것

운영 반영은 B가 한다(team-handoff §6). `script.py` 는 이 작업에서 건드리지 않았다.

1. **#96 게이트가 `[수요기관(기초자치단체)]` 를 기초 신호로 못 읽는다.** `v6_not_a_basic_region_limit()`
   의 조건 ②가 `PPS-DEV-071` 의 인용을 "지역제한 문장이 아니다"로 읽어 내린다(실측). 그래서 이
   후보는 v6 만 제출 후처리 **뒤**에 얹는다. 운영에 옮길 때는 `_has_basic_unit()` 이 이 토큰을
   배워야 하고, 그러지 않으면 U 가 올린 `071` 이 게이트에서 도로 내려간다.
2. **`script.BASIC_REGION_NAME` 이 보통 낱말을 기초 지명으로 읽는다.** `[가-힣]{2,4}(?:시|군|구)`
   라서 **`체결시`·`반드시`** 를 문다. 처음 이 함수 하나로 올림·내림을 다 했을 때
   `PPS-DEV-32`·`PPS-DEV-076` 에 붙어 dev 오탐 2건이 났다. 이 후보는 방향마다 신호를 갈랐다 —
   **올리는 쪽은 익명화 토큰만**(dev 는 전부 익명화라 기초 지명은 토큰으로 온다), **내리는 쪽은
   이름까지**(의심스러우면 안 내린다). 운영 게이트는 내리는 쪽에만 쓰므로 지금 당장 틀리지는 않지만,
   올리는 규칙을 옮길 때 같은 함수를 그대로 쓰면 이 오탐이 따라온다.
3. **후보가 `script.py` 를 한 벌 더 적재하고 있었다.** `tools/replay_run.py` 는 제출 코드를
   `sys.modules["submission"]` 에 등록하고 "후보가 저장소 루트의 script.py 를 따로 읽지 않게"
   한다고 적어 두었는데, `_submission()` 이 그것을 무시했다. 그래서 **규칙을 하나도 켜지 않은
   재생이 main 과 v11 4셀·v12 1셀 어긋나고 Macro 가 0.020707070707 내려갔다.** 사본은 재생이
   `load_sme_reference()` 로 채운 참조표를 모른다. 이 후보로 v3 을 쟀던 이전 측정에도 걸려 있던
   결함이다 — 그 수치를 다시 쓸 일이 있으면 재생부터 다시 해야 한다.

## 하지 않은 것

- `script.py` 를 고치지 않았다. 운영 반영은 B의 몫이다.
- 20,000건 전수를 재지 않았다. 무라벨 수치는 **2,000건 회차**이고 그 회차의 코드는 `14f03d1` 이다.

  전문공사를 가를 수 없다. 확인 못 한 것으로 두므로 공사 공고에서 L2 는 내리지 않는다.
- 이 측정은 **발화율이지 정확도가 아니다.** 무라벨에는 정답이 없다.
