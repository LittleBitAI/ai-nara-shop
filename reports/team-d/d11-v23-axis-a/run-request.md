# D11 v23 축 A — Colab 실행 안내

상태: **GPU 미실행.** 회차 1회를 돌려 결과 ZIP 하나를 받는다.
이 후보는 **모델 뒤 단계(`postprocess`)만 바꾼다.** 프롬프트·스키마·호출 수가 그대로여서
`docs/workflow.md` W5 상 유효한 측정은 이미 끝난 **CPU 재생**이다(아래 §측정된 것).
이 회차의 목적은 점수 판정이 아니라 **운영 환경 확인**이다.

## 이 회차가 가를 수 있는 것과 없는 것

| | |
| --- | --- |
| 가른다 | 새 `script.py` 가 GPU 환경에서 죽지 않는가(`from datetime import date` 추가·새 정규식 12개) |
| 가른다 | 새 모델 응답에서도 v23 판정이 재현되는가 — 후처리 규칙이라 원응답과 무관하게 같아야 정상 |
| 가른다 | 서버 시간 예산(호출 수 불변이므로 변화 없어야 정상) |
| **못 가른다** | **이 변경의 Macro 기여.** 증분이 `+0.004629629630`(H2) 인데 같은 코드 열한 쌍의 churn 폭이 `0.000008~0.004689` 다(W5). 회차 한 쌍의 Macro 차이는 신호가 아니다 |

그래서 결과는 Macro 가 아니라 **v23 TP/FP/FN 과 v23·e23 밖 셀 수**로 읽는다.

## 실행

1. 노트북 `notebooks/colab-baseline.ipynb` 를 Colab 에 올리고 A100 GPU 를 고른다.
2. 첫 셀의 `REPO_REF` 를 **`feat/d-v23-axis-a`** 로 바꾼다(브랜치 이름 그대로 쓴다).
   실행 코드는 그 브랜치의 `5b28715e8210256514fe39320311ee59b38a9539` 다. 40자리 SHA 를
   그대로 넣어도 된다 — 약칭 SHA 는 노트북이 clone 전에 거부한다.
3. `HF_TOKEN` 보안 비밀과 노트북 접근 권한을 켠다.
4. 위에서부터 전부 실행한다. `RUN_DIAGNOSTIC = True` 를 유지한다(원응답 보관, 약 15분 추가).
5. 마지막 셀에서 `colab-results-*.zip` 을 받는다. 중간 셀이 실패했어도 마지막 셀은 따로 실행한다.
