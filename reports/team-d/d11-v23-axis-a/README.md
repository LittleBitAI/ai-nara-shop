운영 `script.py` 가 v23 을 코드로 정한다. **v23 한 항목만 바꾼다.**

## 조문

(행안부예규) 지방자치단체 입찰시 낙찰자 결정기준 **제7장 제3절 2-다**

> 제출마감일의 전일부터 기산하여 다음 각호의 어느 하나에 해당하는 기간 전에 실시해야

## 판정

`v23_applies(rec)` — 적용계약법 지방 + 낙찰방법 협상. 밖은 0 이다([items](../../../docs/items.md) v23).
안에서는 `v23_axis_a(rec)` 가 세 값을 다 읽었을 때만 판정한다.

| | 어디서 | 못 읽으면 |
| --- | --- | --- |
| 필요기간 | `meta.입찰추정가격` → 40/20/10일 | 올리지 않는다 |
| 설명일 | 공고 원문. 공고게시일 이후의 가장 이른 날짜 | 올리지 않는다 |
| 제출마감일 | **공고 원문** | 올리지 않는다 |

`(마감일 − 설명일).days < 필요기간` 이면 1, 근거는 설명 문장이다.

### 마감일에 `meta.개찰예정일자`를 쓰지 않는 이유

`PPS-DEV-27` 은 개찰이 2/20 인데 실제 제안서 제출마감은 2/6 이다. 메타로 대체하면 열나흘을
잘못 세어 위반을 놓친다. 원문 앵커는 두 단이고, 마감이라고 스스로 말하는 자리를 먼저 본다.

### 설명회의 이름은 판별력이 없다

정답 양성 다섯이 다섯 표기를 하나씩 쓴다 — `사업설명회`(27) · `제안요청 설명회`(28) ·
`현장설명회`(139) · `과업설명회`(140) · `제안요청서 설명`(141). 조문 용어는 「제안요청서 등에
대한 설명」 하나다. 그래서 이름이 아니라 **절차 위치**로 거른다.

| 거르는 것 | 근거 | 실례 |
| --- | --- | --- |
| 제안서 **평가** 단계의 설명 | 제3절 4-아. 제출마감 **뒤** 단계라 기간 규정의 대상이 아니다 | `PPS-DEV-109` — `설명시간 : 업체당 40분 내외(제안설명 20분, 질의응답 20분)` |
| 설명일이 마감일보다 뒤인 것 | 기간을 셀 수 없다 | `PPS-DEV-143` — `사업설명회 개최 … 착수일로부터 2026. 9. 30.까지`(과업 내용) |
| 날짜가 공고에 없는 것 | 위반을 증명할 수 없다 | `PPS-DEV-136` — `현장설명회를 개최하며(일시·장소는 개별 통보)` |

평가 단계 검사는 걸린 자리 **±40자**만 본다. 창 120자로 보면 바로 다음 항목
(`7. 제안서 발표 및 평가`)이 걸려 `PPS-DEV-140` 의 정탐이 같이 죽는다(실측).

## 설명하지 못한 반례 — `PPS-DEV-191`

`사업설명회 2026. 6. 2.` · `입찰등록, 제안서 제출 ~ 2026. 6. 9. 15:00` · 추정가격 1.045억

배제 근거를 법령 패키지에서 찾지 못했다. 검증해서 기각한 가설은 넷이다.

남은 유일한 성문 차이는 191 공고만 근거 법령을 **「준용」**이라 적는다는 것이다
(`시행령 제43조, 제44조 준용` · `예규 제344호 준용`). 28·139·109 는 `…에 따라`·`…에 의거`로

못 가른다. 그래서 규칙에 넣지 않았다.

**이번 변경은 191 을 막지 않는다.** 191 의 표기(`제안서 제출 ~` 다음 줄에 날짜, 꼬리말 없음)가
