# D10 — v6 U 규칙을 운영 `script.py` 로 옮긴다

PR #114 에서 후보(`experiments/qualification_candidate.py`)로 검증한 v6 올림 규칙 U 를
운영 후처리로 이식한 기록이다. v6 한 항목만 바꾼다.

## 무엇을 옮겼나

`v6_should_raise(rec)` 가 모델이 v6=0 을 낸 자리에서 근거를 찾아 1 로 올린다. 조건 셋이다.

| | 조건 |
| --- | --- |
| ⓐ | 참가자격 문맥의 지역 제한 문장에 토큰으로 확인된 기초 신호가 제한 대상과 묶여 있다 |
| ⓑ | 추정가격 < `region_price_limit(rec)` |
| ⓒ | 지방 소액수의견적이 아니다 — 예외 범위를 확인할 수 없으므로 올리지 않는다 |

관계 판정은 후보에서 리뷰 여섯 라운드로 굳힌 긍정 근거 방식 그대로다. 지역 제한 문장은
두 꼴 중 하나이고, ①의 주어는 참가 업체의 것이어야 한다(`납품장소의 소재지` 는 머리가
장소이므로 주어가 아니다).

| 꼴 | 구조 |
| --- | --- |
| ① 주어–서술 | `<참가 업체의 소재지 주어>` … `<지역>` … `<두다·소재하다·있다>` |
| ② 융합 | `지역제한(<지역>)` · `<지역> 지역 업체` |

## 호출 위치 — 내리는 게이트 뒤

앞에 두면 `v6_not_a_basic_region_limit()` 이 U 의 근거를 다시 보고 지울 수 있다. 대신
`v6_should_raise()` 안에서 `_v6_evidence_supports_v6()` 이 같은 계약을 스스로 건다 —
근거가 비지 않았나, 인용 안에 기초 토큰이 남았나.

그리고 모델이 v6=0 을 낸 자리에서만 올린다. 게이트가 내린 셀(모델은 1 이라 했다)까지
올리면 측정한 적 없는 다른 규칙이 된다 — 무라벨 2,000건에서 7건이 18건으로 늘어난다(실측).

## 근거 인용은 묶인 토큰에 맞춘다

도막이 480자를 넘으면 인용을 잘라야 하는데, 그 창을 도막 안의 아무 지역 토큰이 아니라
제한과 실제로 묶인 그 토큰에 맞춘다. `ANON_REGION` 이 `단위=광역` 도 물기 때문에,
앞선 광역 토큰을 중심으로 잡으면 924자짜리 참가자격 줄에서 정작 기초 토큰이 인용 밖으로
밀리고 근거 계약이 깨져 정탐을 놓친다(PR #128 리뷰 P2, 재현 확인).

그래서 `_v6_binds()` 가 참/거짓이 아니라 묶인 토큰의 위치를 돌려주고,
`v6_basic_region_limits()` 가 `(문서, 도막, 토큰)` 을 넘긴다. 검사는 같은 줄을 20회·65회
반복으로 늘려 상한 앞뒤 양쪽을 고정한다.

크기로 나오지 않는다는 경고다.

후보와의 대조: 1회차 7건이 PR #114 의 후보 측정과 같은 목록이고, 23건 전체를 후보의
